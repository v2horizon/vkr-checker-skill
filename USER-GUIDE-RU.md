# vkr-mpgu 6.33 — инструкция для пользователя

Это руководство для студента или преподавателя, который хочет писать и проверять
выпускную квалификационную работу (ВКР) с помощью ИИ-агента и этого скилла.
Техническая установка подробно описана в `vkr-mpgu/INSTALL-RU.md`, работа агента
шаг за шагом — в `vkr-mpgu/references/quickstart.md`. Здесь — то, что нужно знать
именно вам.

## 1. Что скилл делает и чего не делает

Скилл превращает ИИ-агента в помощника по ВКР, который:

- проводит интервью и создаёт отдельную папку проекта с черновиками, реестром
  источников, планом и памятью между сессиями;
- пишет и правит текст по методике МПГУ (обычная и проектная ВКР, профиль
  09.03.02 сверен с методичкой ИМО 2024 года; другие программы — по общему ГОСТ);
- собирает единственный сдаваемый файл `final/vkr.docx` с правильным оформлением
  (A4, Times New Roman 14, поля 35/10/20/20 мм, интервал 1,5, оглавление,
  нумерация, список литературы по алфавиту, автоматическая перенумерация ссылок);
- пишет в живом академическом стиле по `references/humanizer-techniques.md`:
  без ИИ-клише, с вариативностью фраз и конкретикой вашей работы — и сам
  проверяет текст эвристикой `ai_detection_heuristic.py`; против плагиата —
  глубокий парафраз и синтез по `originality-techniques.md`;
- проверяет оформление, источники, логику и стиль, ведёт независимый аудит
  несколькими проверяющими агентами и выдаёт машинный статус готовности;
- умеет взять уже написанный DOCX, перенести его в черновики и вернуть в них
  ваши правки, сделанные в Word.

Скилл **не делает** за вас:

- не выдумывает источники, результаты, участников пилота, подписи и справки —
  всё это должны предоставить вы;
- не заменяет научного руководителя и кафедру: статус «готово» означает только,
  что автоматические проверки пройдены;
- не гарантирует прохождения Антиплагиата или детектора ИИ: стилистические
  техники снижают риск, но архитектура детекторов закрыта и меняется. Технические
  трюки (латиница вместо кириллицы, скрытый текст, символы нулевой ширины,
  синонимайзеры) скилл не применяет — их детектируют отдельно, и это уже
  дисциплинарная ответственность;
- не решает, разрешено ли использовать ИИ в вашем вузе. Спросите на кафедре и
  сообщите агенту правила — он учтёт их (в том числе укажет использование ИИ во
  введении, если это требуется).

## 2. Что понадобится

| Что | Зачем |
|---|---|
| ИИ-система с доступом к файлам и запуску Python: Codex, Claude Code, Cursor, Windsurf, GitHub Copilot, Gemini CLI, OpenCode или похожая | агент читает и пишет файлы проекта и запускает проверки |
| Python 3.9 или новее + `python-docx` + `PyYAML` (`python -m pip install python-docx pyyaml`) | сборка и проверка DOCX |
| Microsoft Word (Windows) — желательно | автоматическое обновление оглавления; без Word агент попросит нажать F9 в Word/LibreOffice |
| Веб-поиск у агента | проверка, что источники реально существуют |
| Ваши материалы: тема, методичка кафедры (если есть), описание продукта, данные пилота, скриншоты, уже написанные фрагменты | без них агент не сможет честно заполнить работу |

Веб-чаты без доступа к файлам (обычный ChatGPT, claude.ai без импорта навыков)
тоже подходят, но с ограничениями: проверки нужно запускать самому, а независимый
аудит будет «ослабленным» (`degraded_independence`) — итог не выше «готово к
показу руководителю». Как подключить в таком случае — `vkr-mpgu/PORTABLE-PROMPT.md`.

## 3. Установка

Скачайте один файл со страницы релизов
<https://github.com/v2horizon/vkr-checker-skill/releases>: `vkr-mpgu-6.33-production.zip`
или `vkr-mpgu-6.33-production.skill` (содержимое одинаковое, SHA-256 обоих файлов
`21420c206e5d4f1eb7c0ca9553d3e7feb6b25e00a34701dad2e7a2f00d1627b0`). Затем:

| Где работаете | Что сделать |
|---|---|
| **Codex** | распакуйте ZIP в `~/.codex/skills/` (готовый блок команд — в README, раздел «Вариант B»); вызов: `$vkr-mpgu помоги начать ВКР с нуля` |
| **Claude Code** | распакуйте ZIP в `~/.claude/skills/` (тот же блок, в строке `skills=` замените `.codex` на `.claude`); вызов: `/vkr-mpgu помоги начать ВКР с нуля` |
| **Claude Desktop / claude.ai** | импортируйте файл `.skill` через «Import skill»; затем обычный запрос: «помоги начать ВКР с нуля». Если раньше был подключён старый `vkr-mpgu`, отключите его, иначе загрузятся две версии |
| **Cursor, Windsurf, GitHub Copilot, OpenCode** | клонируйте репозиторий или распакуйте ZIP в отдельную папку; откройте её в редакторе — агент прочитает `AGENTS.md` / `.cursor/rules` / `.github/copilot-instructions.md`. Работу ведите в **другой** папке (проект ВКР), не внутри папки скилла |
| **Gemini CLI** | то же, что для Cursor: агент прочитает `GEMINI.md` |
| **Веб-чат или API** | по `vkr-mpgu/PORTABLE-PROMPT.md`: инструкция проекта + загрузка файлов скилла |

Проверка: файл `.../vkr-mpgu/SKILL.md` существует и содержит `6.33-production`.
Обновление со старой версии: сначала уберите старую папку из каталога навыков
(подробно — README, «Порядок обновления»), потом ставьте новую.

## 4. Первый запуск: интервью

Напишите агенту, что хотите начать ВКР (или доработать готовый черновик), и
ответьте на вопросы. Он спросит:

1. вуз, институт, кафедру, направление (код и название), профиль, группу;
2. научного руководителя (должность, степень, ФИО) и заведующего кафедрой;
3. тему, тип ВКР (обычная или проектная) и срок сдачи — от срока зависит режим
   работы (стандартный или экспресс);
4. что уже есть: продукт, пилот, данные, источники, написанные фрагменты;
5. правила кафедры об использовании ИИ.

Подготовьте эти ответы заранее — они попадут на титульный лист и в план работы.
После интервью агент сам создаст папку проекта (`vkr-project.json`, `vkr-state.md`,
`plan.md`, `drafts/`, `sources.json`, `evidence/`, `audit/`, `memory/`, `final/`,
`exports/`). Ничего создавать вручную не нужно.

## 5. Как идёт работа

- **Текст** живёт в черновиках `drafts/*.md` (введение, главы, заключение,
  аннотация, приложения). DOCX всегда собирается из них — правьте либо черновики,
  либо DOCX в Word с последующим возвратом правок (раздел 7), но не то и другое сразу.
- **Источники** хранятся в реестре `sources.json`. Агент обязан проверить каждый
  источник реальным поиском и отметить проверку; непроверенные помечаются
  `[ПРОВЕРИТЬ]`. Если вы даёте свои источники — давайте точные выходные данные.
- **Утверждения и доказательства.** Ключевые цифры, результаты пилота, функции
  продукта агент записывает в реестр утверждений и просит положить доказательства
  (таблицы, скриншоты, код, анкеты) в `evidence/`. Без доказательств утверждение не
  считается подтверждённым.
- **Аудит.** На контрольных точках (план, глава, сборка, финал) агент запускает
  независимых проверяющих — отдельных агентов, которые только ищут ошибки. Замечания
  исправляет основной агент, затем новые проверяющие перепроверяют. Это занимает
  время; в экспресс-режиме проверок меньше.
- **Сборка.** Команда сборки создаёт `final/vkr.docx`, затем агент обновляет
  оглавление через Word (или попросит вас нажать Ctrl+A, F9 и сохранить), очищает
  метаданные и проверяет оформление.
- **Статусы готовности** (их выдаёт проверка `doctor`):
  - `READY_FOR_SUPERVISOR_REVIEW` — можно показывать руководителю; допустимы
    непроверенные источники и открытые мелкие замечания;
  - `READY_TO_SUBMIT` — пройдены все проверки, независимый аудит в два этапа,
    источники подтверждены, объём в аннотации совпадает с файлом;
  - `NOT_READY` — есть что исправить; агент получает список следующих шагов.

## 6. Что делать вам по ходу

- Отвечать на вопросы по существу и давать реальные данные. Если данных нет
  (пилот не проведён), скажите прямо — агент оставит место и не будет придумывать.
- Читать написанное. К защите вы должны уметь объяснить каждый абзац; для этого
  есть проверка владения материалом (Test-30) и список вопросов комиссии.
- Проверять предупреждения валидатора, о которых сообщит агент: объём глав,
  ключевые слова в аннотации, не упомянутые в тексте источники и т. п.
- Показать работу научному руководителю на статусе
  `READY_FOR_SUPERVISOR_REVIEW`, а не ждать финала.

## 7. Правки в Word

Открывать `final/vkr.docx` в Word для чтения можно всегда. Если вы **правите**
текст в Word:

1. сохраните файл;
2. скажите агенту: «я правил(а) DOCX в Word, перенеси правки» — он выполнит
   `import_docx.py --update`, правки попадут в черновики, ссылки на источники
   сохранятся;
3. агент пересоберёт DOCX и заново проведёт проверки.

После финального аудита файл лучше не открывать на запись: любое изменение байтов
требует нового снимка и повторных проверок. Для отправки руководителю используйте
копию в `exports/`.

## 8. Продолжение в новом чате

Откройте ту же папку проекта и напишите агенту: «продолжаем ВКР, проект в папке
…». Он прочитает `vkr-state.md`, память (`memory/`) и журнал аудита, сверит хеши
файлов, сообщит, где остановились, и предупредит, если что-то менялось вне сессии.
Ничего пересказывать заново не нужно.

## 9. Уже есть черновик

Скажите агенту, что есть готовый DOCX. Он создаст проект и импортирует файл:
главы станут черновиками, список литературы — реестром источников, код —
листингами, рисунки — файлами в `evidence/figures`. Дальше путь тот же:
проверка источников, аудит, пересборка. Типичные ошибки оформления (шрифт, поля,
арабские номера глав, порядок литературы, ссылка в заключении) исправляются или
показываются автоматически.

## 10. Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| Агент не находит скилл или отвечает «не той» версией | проверьте путь `…/skills/vkr-mpgu/SKILL.md` и строку `6.33-production`; на claude.ai отключите старый `vkr-mpgu` в настройках аккаунта; начните новую сессию |
| «python-docx не установлен» | `python -m pip install python-docx pyyaml` |
| «Оглавление НЕ обновлено» | откройте DOCX в Word: Ctrl+A, F9 → «Обновить целиком», сохраните; либо дайте агенту запустить `update_docx_fields.py` (Windows + Word) |
| «Word не открыл файл» / файл повреждён | пересборка: агент выполнит `build_vkr.py` → обновление полей → очистку; не правьте XML вручную |
| `FAIL` у проверки `doctor` | это нормальный рабочий статус; агент читает `next_actions` и исправляет по списку |
| Кракозябры в PowerShell | читайте отчёты из файлов (`-o`) или выполните `$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new()` |
| Агент «подтвердил» источник, которого вы не знаете | попросите показать, где он его нашёл (URL, каталог); без реальной ссылки источник должен остаться непроверенным |

## 11. Ответственность

Скилл помогает написать, оформить и проверить работу, но автор работы — вы.
Подтверждайте факты, читайте текст, проверяйте источники, соблюдайте правила своего
вуза об использовании ИИ. Финальное решение о содержании и допуске к защите
принимают автор и научный руководитель.
