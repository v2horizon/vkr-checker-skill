# AGENTS.md — точка входа для ИИ-агентов

Этот репозиторий содержит **AI-скилл `vkr-mpgu` версии `6.33-production`** —
инструкцию и инструменты для подготовки, оформления и проверки выпускной
квалификационной работы (ВКР) по методическим рекомендациям МПГУ и ГОСТ.
Файл читают агенты, которые поддерживают соглашение `AGENTS.md`: Codex, Cursor,
Windsurf, GitHub Copilot, OpenCode и другие.

## Нормативная инструкция

- [vkr-mpgu/SKILL.md](./vkr-mpgu/SKILL.md) — **главный документ**: методика,
  порядок работы, контрольные точки. Прочитай его до начала работы.
- [vkr-mpgu/references/quickstart.md](./vkr-mpgu/references/quickstart.md) —
  сквозной путь с командами и ожидаемыми результатами.
- [README.md](./README.md) → раздел «Инструкция для ИИ-агента» — блок
  `AI_AGENT_BOOTSTRAP`, единственный источник правил запуска. Полный список
  шагов бери там, здесь только выжимка.
- [vkr-mpgu/references/platform-integration.md](./vkr-mpgu/references/platform-integration.md)
  — что делать, если платформа не умеет запускать Python, работать с файлами
  или создавать отдельные контексты.

## Семь правил, без которых работа ломается

1. Рабочие файлы ВКР живут в **отдельной папке проекта** `<PROJECT_DIR>`, а не в
   клоне скилла. Установленную папку скилла во время работы не редактируй.
2. Новый проект: intake-интервью (включая правила кафедры об использовании ИИ) →
   `intake.json` → `init_vkr_project.py`. Структуру каталогов пользователь
   вручную не создаёт.
3. Существующий проект: прочитай `vkr-state.md`, `memory/handoff.json`,
   `memory/roadmap.md`, `audit/manifest.json`, затем запусти `vkr_memory.py status`
   и `vkr_audit.py next` — и только потом продолжай работу.
4. Текст пиши в `drafts/*.md`, DOCX собирай `build_vkr.py`. Сдаётся ровно один
   файл — `final/vkr.docx`; промежуточные сборки и отчёты — в `exports/`.
5. Источники проверяй фактически доступным веб-поиском и отмечай
   `verify_sources.py --mark`. Не выдумывай источники, результаты, пилоты и
   подписи: галлюцинированный источник — главный риск для работы.
6. Аудит ведут только команды `vkr_audit.py`: аудиторы работают на чтение,
   исправляет основной агент, служебные поля отчётов вручную не пишутся. Если
   отдельные контексты (субагенты) недоступны, аудит помечается
   `degraded_independence` и итог не выше `READY_FOR_SUPERVISOR_REVIEW`.
7. `READY_TO_SUBMIT` выдаёт только `vkr_project_doctor.py --stage final`. Не
   обещай безошибочность: проверка кафедры и научного руководителя обязательна.

## Как вызвать скилл

| Среда | Вызов |
|---|---|
| Codex | `$vkr-mpgu помоги начать ВКР с нуля` |
| Claude Code | `/vkr-mpgu помоги начать ВКР с нуля` |
| Cursor, Windsurf, Copilot, OpenCode | обычный запрос о ВКР — правила подхватываются из этого файла и `.cursor/rules/vkr-mpgu.mdc` |
| Gemini CLI | обычный запрос о ВКР, инструкция — в [GEMINI.md](./GEMINI.md) |
| Веб-чат или API | [vkr-mpgu/PORTABLE-PROMPT.md](./vkr-mpgu/PORTABLE-PROMPT.md) как постоянная инструкция проекта |

Установка отдельной копией скилла — [vkr-mpgu/INSTALL-RU.md](./vkr-mpgu/INSTALL-RU.md).
Скрипты запускаются как `python <SKILL_DIR>/scripts/<имя>.py`, где `<SKILL_DIR>` —
папка `vkr-mpgu` этого репозитория или установленная копия.
