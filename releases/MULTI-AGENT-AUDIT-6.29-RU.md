# Многоагентный контур `vkr-mpgu 6.29-independent-audit`

## Принятая архитектура

Основной ИИ-агент остаётся единственным автором изменений. Он проводит интервью,
пишет ВКР, получает замечания и исправляет документ.

Независимые агенты:

- получают одну зафиксированную версию ВКР с SHA-256;
- работают в отдельных контекстах и не видят выводы друг друга;
- имеют доступ к документу только на чтение;
- возвращают ошибки с местом, критерием, доказательством и предложенным способом
  исправления;
- никогда не редактируют ВКР;
- после исправлений заменяются новыми независимыми агентами для recheck.

Таким образом, основной агент не проверяет и не одобряет собственную работу без
внешнего контура, а несколько аудиторов не конкурируют за запись в один файл.

## Независимые роли

| Код | Проверка |
|---|---|
| `MET` | Методичка, профиль, структура и обязательные элементы |
| `SRC` | Реальность источников, реквизиты, DOI/URL, цитаты и поддержка тезисов |
| `LOG` | Логика темы, цели, задач, методов, глав, результатов и выводов |
| `LNG` | Орфография, пунктуация, грамматика, синтаксис и терминология |
| `STY` | Академический стиль, ИИ-клише, монотонность и повторяемость |
| `EVD` | Реальность продукта, кода, чисел, пилота и результатов |
| `DOC` | DOCX, форматирование, TOC, таблицы, рисунки и визуальный контроль |
| `OWN` | Владение материалом и возможные вопросы комиссии |

Для большого списка источников `SRC` запускается несколькими независимыми
пакетами. Высокорисковые источники и прямые цитаты перепроверяются вторым
агентом.

## Цикл работы

1. Основной агент замораживает вход и создаёт `audit/manifest.json`.
2. Запускаются штатные Python-проверки.
3. Восемь независимых аудиторов проводят слепую проверку.
4. Основной агент объединяет доказанные замечания в `audit/fix-plan.md`.
5. Основной агент последовательно исправляет ВКР и фиксирует журнал изменений.
6. Формируется новый снимок и новый SHA-256.
7. Новые независимые аудиторы проверяют исправленную версию и ищут регрессии.
8. Незакрытые ошибки возвращаются основному агенту; цикл повторяется.

Аудиторы не придумывают факты и не закрывают ошибки литературной редактурой.
Если нужны реальные даты, участники, исходные данные, код или PDF источника,
замечание получает статус `USER_DATA_REQUIRED`.

## Gate готовности

`READY_TO_SUBMIT` возможен только при общем финальном SHA-256, завершении всех
восьми ролей, отсутствии открытых `BLOCKER` и `MAJOR`, подтверждении источников,
фактов продукта и пилота, нулевом результате формального валидатора, обновлённом
оглавлении, визуальной проверке DOCX и успешном повторном аудите после последней
правки.

Подробный исполняемый протокол находится в
`vkr-mpgu/references/multi-agent-audit.md`.
