# GEMINI.md — точка входа для Gemini CLI

Репозиторий содержит **AI-скилл `vkr-mpgu` версии `6.33-production`** — инструкцию
и инструменты для подготовки, оформления и проверки выпускной квалификационной
работы (ВКР) по методическим рекомендациям МПГУ и ГОСТ. Платформенно-нейтральный
вариант этих же правил — [AGENTS.md](./AGENTS.md).

## Нормативная инструкция

- [vkr-mpgu/SKILL.md](./vkr-mpgu/SKILL.md) — главный документ скилла: методика,
  порядок работы, контрольные точки. Читается до начала работы.
- [vkr-mpgu/references/quickstart.md](./vkr-mpgu/references/quickstart.md) —
  сквозной путь с командами и ожидаемыми результатами.
- [README.md](./README.md) → «Инструкция для ИИ-агента» — блок
  `AI_AGENT_BOOTSTRAP`, единственный источник правил запуска; ниже только выжимка.
- [vkr-mpgu/references/platform-integration.md](./vkr-mpgu/references/platform-integration.md)
  — что делать, если недоступны Python, файлы или отдельные контексты.

## Ключевые правила

1. Рабочие файлы ВКР — в отдельной папке проекта `<PROJECT_DIR>`, не в клоне
   скилла; клон при работе над ВКР не редактируется.
2. Новый проект: intake-интервью (включая правила кафедры об использовании ИИ) →
   `intake.json` → `init_vkr_project.py`.
3. Существующий проект: сначала `vkr_memory.py status` и `vkr_audit.py next`,
   потом продолжение работы.
4. Текст — в `drafts/*.md`, сборка — `build_vkr.py`, сдаётся только
   `final/vkr.docx`; промежуточное — в `exports/`.
5. Источники подтверждай веб-поиском и отмечай `verify_sources.py --mark`. Не
   выдумывай источники, результаты, пилоты и подписи.
6. Аудит — только командами `vkr_audit.py`: аудиторы работают на чтение,
   исправляет основной агент.
7. `READY_TO_SUBMIT` выдаёт только `vkr_project_doctor.py --stage final`.

## Вызов и особенности среды

Отдельной команды не требуется: достаточно обычного запроса о ВКР — скилл
подхватывается из этого файла. Скрипты запускаются как
`python <SKILL_DIR>/scripts/<имя>.py`, где `<SKILL_DIR>` — папка `vkr-mpgu`
этого репозитория; нужен Python 3.9+ с `python-docx` и `PyYAML`.

Если среда не создаёт отдельные контексты для аудиторов, роли выполняются
последовательно, run помечается `degraded_independence`, и готовность не
поднимается выше `READY_FOR_SUPERVISOR_REVIEW`. Веб-поиск обязателен для проверки
источников; без него места помечаются как непроверенные, а не объявляются
проверенными.
