# Методичка МПГУ: требования к ВКР

Это Markdown-свод методички МПГУ, встроенный в скилл. Он сверён с документом
`assets/methodology-09-03-02-2024.docx` (SHA-256:
`8d890c1474c0621a8e5259b514126935c92d94393127c2d27094fa80cb447eae`); для профилей
`mpgu-*` init копирует его в проект как `sources/materials/methodology-09-03-02-2024.docx`.

**Что это за документ.** Файл содержит два раздела: «Требования к структуре и
оформлению выпускной квалификационной работы (бакалаврской диссертации)» и те же
требования «в формате проекта», с формой справки о внедрении в Приложении 2. Кода
направления в тексте нет; форма справки называет «Институт международного
образования», образцы титула и разрешения документ отсылает искать в группе
ВКонтакте `imo_mpgu`. Скилл использует документ как базовый профиль 09.03.02,
потому что он предоставлен для этой программы; пока студент не дал более свежий
официальный документ своей программы, этот файл — основная встроенная методическая
база. Правила приоритетов описаны в `requirements-precedence.md`.

Для студента источником истины являются актуальные документы его кафедры,
программы и года сдачи. Если их нет, этот файл применяется как базовый профиль.
При конфликте локальной методички с общим ГОСТ приоритет обычно имеет локальная
методичка, если кафедра не указала иное.

## 1. Общие требования

### Объём

- **Обычная ВКР бакалавра:** 50–60 стр. (A4, односторонняя печать)
- **ВКР в формате проекта:** 40–50 стр. без учёта приложений и списка литературы

### Ориентиры объёма глав

Методички задают общий объём, но не устанавливают число страниц по главам.
Диапазоны ниже — рабочие ориентиры скилла для сбалансированного черновика.

**Для проектной ВКР (40–50 стр. суммарно):**
| Глава | Рекомендуемый объём |
|-------|---------------------|
| Глава I (теоретическая) | 10–12 стр. |
| Глава II (аналитическая) | 10–12 стр. |
| Глава III (проектная) | 12–15 стр. |

**Для обычной (теоретической) ВКР (50–60 стр. суммарно):**
| Глава | Рекомендуемый объём |
|-------|---------------------|
| Глава I (теория) | 15–20 стр. |
| Глава II (анализ/эмпирика) | 15–20 стр. |
| Глава III (если есть) | 10–15 стр. |

Восемь страниц на главу — эвристический сигнал дисбаланса, а не подтверждённое
условие допуска. Короткая глава допустима, если её функция раскрыта и структура
утверждена научным руководителем.

**В экспресс-режиме черновика** скилл использует 8–12 стр. на теоретическую/аналитическую главу и 10–12 стр. на проектную как рабочий ориентир. Это не подтверждает допуск сокращённой итоговой работы: перед сдачей проверяется общий объём и утверждённый план; см. `writing-workflow-express.md`.

Остальные файлы скилла используют эти числа только как ориентиры и не должны
называть их формальными порогами допуска.

### Количество источников в списке литературы

Методички конкретное число не задают. Значения ниже — целевые ориентиры для
глубины обзора, которые нужно сверить с кафедрой:

| Режим | Рабочий ориентир скилла |
|-------|--------------------------:|
| Проектная ВКР (стандарт) | **25–50** |
| Теоретическая / обычная ВКР (стандарт) | **30–60** |
| Экспресс (любого типа) | 20–30 с последующей проверкой достаточности |

**Пояснение:** количество само по себе не подтверждает качество. Каждый источник
должен существовать, поддерживать конкретный тезис и быть использован в тексте.
Валидатор сообщает о малом числе ссылок как об информационном сигнале; формальный
минимум задаётся только документом кафедры.

Прошлые IT-работы содержат от 4 до 30 заявленных источников, поэтому использовать
их как доказательство минимума нельзя. Подробности — `requirements-precedence.md`.

- При специфике темы может быть чуть больше или меньше

### Язык

Работа выполняется **на русском языке**.

### Антиплагиат

- Проверка в **Антиплагиат.Вуз** — один раз. Доступ к системе есть только у вузов.
- Никакой платный сторонний антиплагиат не эквивалентен.

**Уровни оригинальности (обычная ВКР):**
- 80%+ — «отлично»
- 70–79% — «хорошо»
- 50–69% — «удовлетворительно»
- <50% — «неудовлетворительно»

**Уровни оригинальности (ВКР-проект):**
- 90%+ — «отлично»
- 80–89% — «хорошо»
- 70–79% — «удовлетворительно»
- <70% — «неудовлетворительно»

Оригинальность **не гарантирует** соответствующую оценку. Содержание и защита — тоже важны.

### Переплёт

Любой способ. Твёрдая обложка — по желанию, не обязательна.

### Запреты

- **НЕ использовать личные местоимения** («я», «мы», «нас», «наш»). Заменять на безличные конструкции: «был проведён анализ», «поставленные задачи выполнены».
- В **заключении** не может быть ссылок и цитат.

## 2. Структура ВКР (порядок вшивки)

1. **Титульный лист** — не нумеруется
2. **Аннотация** — нумеруется как страница 2; заголовок «Аннотация» и сам текст
3. **Содержание (Оглавление)** — нумеруется как страница 3. **Важно:** в содержание НЕ включать аннотацию и само оглавление. Список начинается с «Введение».
4. **Введение**
5. **Основная часть**: для обычной ВКР число и названия глав — по утверждённому плану (методичка их не задаёт); для ВКР в формате проекта — три главы (теоретическая, аналитическая, проектная), примерами в методичке даны только параграфы (раздел 7)
6. **Заключение** — без ссылок и цитат
7. **Список использованной литературы** (библиография)
8. **Приложения** (при необходимости)
9. **Последний лист — «клятва»** с подписью и датой от руки

**После клятвы дополнительно вшиваются ТРИ пустых файла-вкладыша** (по приложенной методичке ИМО 2024 г.; для своей программы перечень нужно сверить):
- отзыв научного руководителя (вложит сам научрук)
- разрешение на размещение ВКР в информационных системах МПГУ (с «живой» подписью студента; форму брать в официальной группе ВК института)
- справка о проверке на антиплагиат (предоставляется вузом после проверки)

**Для ВКР-проекта:** методичка содержит форму справки о внедрении. Её
обязательность и место в комплекте нужно сверить с кафедрой; см. раздел 15 и
`structure-project.md`.

**Дополнительно для магистрантов:** рецензия.

**Актуальные образцы титульного листа и разрешения на размещение** публикуются ежегодно в официальной группе ВКонтакте института. Для ИМО МПГУ — https://vk.com/imo_mpgu (искать пост с оформлением ВКР в конце учебного года).

**Коллективный проект:** предоставляется одна сшитая работа, но в клятве — подписи всех участников, и столько разрешений на размещение, сколько участников: разрешение оформляет каждый участник.

## 3. Оформление (жёсткие параметры)

| Параметр | Значение |
|----------|----------|
| Шрифт | Times New Roman |
| Размер | 14 pt |
| Цвет | чёрный |
| Межстрочный интервал | 1,5 |
| Верхнее поле | 20 мм |
| Нижнее поле | 20 мм |
| **Левое поле** | **35 мм** (нестандартно — для подшивки) |
| Правое поле | 10 мм |
| Абзацный отступ | 1,25 см |
| Выравнивание основного текста | по ширине |
| Лишние пустые строки между абзацами | отсутствуют |

### Заголовки

- **Главы** — римскими цифрами: «Глава I. Название», «Глава II. Название». Толкование: правило в обоих разделах документа требует римских цифр; пример в разделе обычной ВКР написан с арабской цифрой, а в разделе проекта — «Глава I.». Скилл следует прямому правилу: сборка печатает «Глава I.», валидатор считает арабскую нумерацию глав ошибкой для профилей `mpgu-*` и предупреждением для `generic`
- **Параграфы** — арабские через точку: «1.1. Название», «1.2. Название»
- Первая буква заголовка — заглавная; остальные — строчные (кроме имён собственных)
- **В конце заголовка точка НЕ ставится**
- Расстояние от заголовка до текста — **15 мм**
- Каждую новую главу **рекомендуется начинать с нового листа**

### Фамилии в тексте

Внутри текста работы **не допускается** использование фамилий без инициалов.

- Правильно: **Н.И. Иванов** (инициалы перед фамилией, через пробел)
- Неправильно: «Иванов считает»
- Исключение: список использованной литературы — там фамилия идёт первой

### Нумерация страниц

- Все страницы, включая иллюстрации и приложения, получают порядковый номер
- Первая страница — титульный лист, но цифра «1» на нём **не ставится**
- Номер страницы — **внизу по центру или справа**

### Принцип единообразия

Если для акцентирования терминов используется курсив — он используется на протяжении всей работы. Выбранный стиль оформления применяется единообразно.

## 4. Аннотация

Объём — **не более 0,5 страницы**. На русском.

Содержит:
1. Название работы
2. Сведения об объёме (количество страниц)
3. Количество использованных источников
4. Перечень ключевых слов
5. Сведения об объекте исследования, цели работы и её актуальности

Количество страниц известно только после сборки DOCX и обновления полей в Word.
Порядок в скилле: сборка (`build_vkr.py`) → `update_docx_fields.py` (число
страниц и `exports/docx-fields.json`) → это число в `drafts/annotation.md` →
пересборка → `update_docx_fields.py` (если объём изменился — повторить).
Подробно — `writing-workflow.md` → «Этап 6: Аннотация»; doctor prefinal/final
сверяет объём в аннотации с числом страниц DOCX (`ANNOTATION_PAGES_MISMATCH`).
В аннотацию идёт полный объём файла по счётчику Word; ориентир методички
«40–50 стр.» относится к текстовой части, и если объём назван с оговоркой
(«без учёта приложений»), doctor только предупреждает
(`ANNOTATION_PAGES_PARTIAL`): сверить объём части работы автоматически нельзя.

## 6. Введение (для обычной ВКР)

Раскрываются:
- актуальность
- проблема
- степень разработанности
- цель
- задачи
- методы
- теоретическая и/или практическая значимость
- объект и предмет исследования
- гипотеза (если применимо)

## 6a. Введение (для ВКР-проекта)

Раскрываются:
- **актуальность** — зачем нужен проект?
- **проблема**, которую решает проект
- **степень разработанности / конкурентный анализ** — как решали до меня?
- **цель** — желаемый результат
- **задачи** — шаги к цели (пересекаются по смыслу с параграфами)
- **гипотеза** — предположение о результате
- **новизна** — для бакалавров опционально, но усиливает работу
- **теоретическая и/или практическая значимость**
- **методологические основы** — ключевые концепции и теории
- **методы** — способы, инструменты, алгоритмы
- **экспериментальная база** — где, как, с кем проводилось пилотирование
- **структура ВКР** — какой объём, из скольких глав и параграфов состоит

## 7. Трёхглавная структура проектной ВКР 09.03.02

Раздел методички о ВКР в формате проекта прямо задаёт основную часть из трёх глав:
теоретической, аналитической и собственно проектной (в перечне структуры они
названы «Глава 1, Глава 2, Глава 3»; оформление глав — римскими цифрами, см.
раздел 3). Для профиля `mpgu-09-project` эта структура обязательна: doctor требует
`drafts/chapter-3.md`. Иное число глав допустимо только для других профилей по
утверждённому плану или прямому указанию научного руководителя; основание
фиксируется в `vkr-state.md`.

### Глава I. Теоретическая часть

Результаты изучения специальной литературы и нормативных документов. Методологическая основа проекта.

Примеры параграфов:
- Характеристика современного состояния исследуемой проблемы
- Методологические подходы к решению проблемы. Выбор методов анализа и проектирования
- Определение пути (путей) решения проблемы

### Глава II. Аналитическая часть

Анализ реального состояния исследуемого объекта.

Примеры параграфов:
- Краткая характеристика исследуемого объекта
- Изучение целевой аудитории
- Анализ состояния исследуемой проблемы в организации
- Анализ конкурентов и альтернативных решений

### Глава III. Собственно проектная часть

Этапы проектирования и разработки.

Примеры параграфов:
- Содержание проекта (цели, структура, логика, формат)
- Дизайн пилотного запуска
- Анализ результатов тестового внедрения
- Разработанные учебные материалы / их образцы

## 8. Этапы ВКР-проекта (что должен включать продукт)

Для профиля `mpgu-09-project` методичка описывает именно образовательный
продукт. Его внедряют в образовательной организации, в подразделении обучения и
развития, на платформе дополнительного профессионального образования либо, по
согласованию, в частной практике. Техническая проверка продукта дополняет, но
сама по себе не заменяет пилотный запуск в этом профиле.

**Этап анализа:**
Ключевые требования к продукту, выводы для методических решений, база для проектирования. Сюда относятся: теоретические основания, выбор и описание целевой аудитории (ЦА), её проблем и потребностей, цель и задачи проекта, анализ конкурентов.

**Этап проектирования:**
Структура образовательного продукта, общая рамка, проектируемые результаты, формат обучения, тематический план, гипотезы.

**Этап пилотирования:**
Тестовый запуск небольшого масштаба для проверки качества, выявления рисков и корректировки. Дизайн запуска, анализ, проверка гипотез, выводы по доработке.

**Этап разработки:**
Наполнение: задания, лекции, мастер-классы, планы занятий. Допустима как полная разработка, так и разработка образцов (части материалов).

**Примеры конечных продуктов:**
- Цифровой (электронный) образовательный ресурс
- Программа курса внеурочной деятельности с методическими и дидактическими материалами
- Банк диагностических заданий
- Иные виды дидактических материалов (по согласованию с научным руководителем)
- Иные виды проектов (по согласованию с научным руководителем и руководителем программы)

**Где может быть реализован проект:**
- В образовательных организациях (школы, СПО, вузы)
- В организациях, не связанных напрямую с образованием (корпоративные отделы обучения, онлайн-платформы ДПО)
- В частной практике, например репетиторство (только по согласованию; для этого случая методичка указывает минимум 5 человек)

## 10. Список использованной литературы

### Главные правила

1. В список включаются **все** источники, упоминаемые в работе
2. Все источники из списка **должны быть отражены в тексте**
3. Список составляется **в алфавитном порядке**
4. Для каждого источника: фамилия автора, название, место издания, год, количество страниц (или диапазон страниц для статьи)

### Примеры (из методички)

**Статья в журнале:**
```
Гарифуллина, А.М. Аллюзии как трансляторы культурных кодов [Текст] /
А.М. Гарифуллина // Вестник ВЭГУ. – 2001. – № 4 (54). – С. 74–79.
```

**Словарь/коллективный труд:**
```
Большой толковый словарь русского языка [Текст] / Сост. и гл. ред.
С.А. Кузнецов. – СПб.: Норинт, 2000. – 1536 с.
```

**Переводная книга:**
```
Рапай, К. Культурный код: Как мы живем, что покупаем и почему [Текст] /
Клотер Рапай; пер. с англ. – М.: Альпина Бизнес Букс, 2008. – 167 с.
```

**Электронный ресурс:**
```
Якобсон, Р. Лингвистика и поэтика // Структурализм: "за" и "против". –
М., 1975 [Электронный ресурс] / Р. Якобсон. – URL:
http://www.philology.ru/linguistics1/jakobson-75.htm (дата обращения:
16.02.21).
```

**Диссертация:**
```
Иванова, С.В. Лингвокультурологический аспект исследования языковых
единиц: Дис. … д-ра филол. наук [Текст] / С.В. Иванова. – Уфа:
Башкирский государственный университет, 2003. – 364 с.
```

**Учебник с переизданием:**
```
Бабенко Л.Г. Лингвистический анализ художественного текста. Теория и
практика: учебник; практикум / Л.Г. Бабенко, Ю.В. Казарин. – 3-е изд.,
испр. – М.: Флинта: Наука, 2005. – 496 с.
```

Полный справочник всех типов записей — см. `gost-citations.md`.

## 11. Оформление ссылок в тексте

**Прямая цитата** — в кавычках; после цитаты в квадратных скобках: номер источника по списку литературы и страница. **Ссылка ставится ДО точки.**

Пример:
```
«Культурный код — это бессознательный смысл, который конкретная культура
придаёт той или иной вещи» [15, с. 23].
```

**Цитата не из первоисточника** (по другому изданию):
```
[Цит. по: 27, с. 235]
[Цит. по кн.: 27, с. 235]
[Цит. по ст.: 27, с. 235]
```

**Парафраз без прямой цитаты** — просто номер источника:
```
Данная концепция получила развитие в работах А.М. Ивановой [12].
```

## 12. Оформление таблиц

1. Если таблица не помещается до конца страницы — переносится на следующую
2. Каждая таблица имеет **заголовок** — над таблицей, по центру, **полужирным**, строчными буквами (кроме первой прописной). В конце точка НЕ ставится.
3. В правом верхнем углу над заголовком — надпись «Таблица N» (без точки после номера)
4. Заимствованная таблица — с обязательной ссылкой на источник
5. Внутри таблиц допустим меньший размер шрифта и одинарный интервал

## 13. Оформление приложений

1. Размещаются **после** списка использованной литературы
2. Каждое — с новой страницы, в правом верхнем углу слово «Приложение N» (например, «Приложение 1»)
3. Каждое приложение имеет **заголовок** — по центру страницы, с прописной буквы, отдельной строкой

## 14. Презентация для защиты

Можно брендированный шаблон PowerPoint МПГУ или собственный.

**Для обычной ВКР презентация содержит:**
1. Новизну работы
2. Какую проблему (научную или практическую) решает исследование (можно гипотезу)
3. Методологию (при необходимости — «рабочий термин»)
4. Методики + выборку (платформы, технологии, тексты — почему выбраны)
5. Суть эксперимента/исследования (пример задания, фото)
6. Результаты исследования
7. Собственные выводы и рекомендации

**Для ВКР-проекта презентация содержит:**
1. Проблему + целевую аудиторию
2. Состояние проблемы и решения конкурентов; новизну
3. Методы проектирования и методологию (на каких теориях построен проект; принцип конструктивной согласованности)
4. Дизайн проекта (структура, модули, цель, предполагаемые эффекты — количественные и качественные)
5. Описание пилотного запуска (где, как, с кем) и его результатов
6. Выводы, рекомендации, перспективы

**Примечания методички.** Для обычной ВКР: после основной части можно подготовить дополнительные слайды для ответов на вопросы комиссии (примеры заданий, фото, графики) — показывать только при необходимости, не во время доклада. Для проекта: если результат — подкасты или видеоуроки, можно показать видеонарезки и выделить слайды для QR-кодов полных версий.

Число слайдов и регламент доклада методичка не задаёт; ориентиры скилла — в `defense.md`.
