# Входной JSON генератора DOCX

Обычно этот JSON писать не нужно: `build_vkr.py` собирает его из черновиков
(`references/drafts-format.md`) в `exports/vkr-content.json` и сразу создаёт
`final/vkr.docx` — единственный сдаваемый файл. Прямой вызов генератора нужен
для отладки или для работы без черновиков:

```text
python <SKILL_DIR>/scripts/create_vkr_docx.py <PROJECT_DIR>/exports/vkr-content.json -o <PROJECT_DIR>/final/vkr.docx [--base-dir <PROJECT_DIR>] [--keep-source-order] [--group-normative-first] [--json]
```

- Файл читается как UTF-8, в том числе с BOM.
- Неизвестный ключ на любом уровне — ошибка с перечнем допустимых ключей
  (ключи, начинающиеся с `_`, считаются комментариями и пропускаются).
- Относительные пути рисунков считаются от `--base-dir`; по умолчанию — каталог
  JSON, а если JSON лежит в `exports/`, то корень проекта.
- Коды: 0 — создан; 1 — содержание нельзя оформить (ссылка на отсутствующий
  источник, запись реестра без обязательных полей, повторяющиеся id, нет файла
  рисунка); 2 — ошибка схемы JSON, чтения/записи файла или нет python-docx.
  С `--json` результат `{status, exit_code, output, errors, warnings}`.

## Ключи верхнего уровня

| Ключ | Тип | Обязателен | Что делает |
|---|---|---|---|
| `title` | строка | да | тема работы (титул, свойства файла) |
| `title_page` | объект | да (`author` или `authors`) | поля титульного листа, см. ниже |
| `annotation` | строка или массив блоков | нет | «Аннотация» (не входит в содержание) |
| `introduction` | строка или массив блоков | нет | «Введение» |
| `chapters` | массив | да, непустой | главы |
| `conclusion` | строка или массив блоков | нет | «Заключение» |
| `sources` | массив записей реестра | нет | структурированный список литературы (схема `sources.json`) |
| `bibliography` | массив строк | нет | готовые строки списка (не сортируются); вместе с `sources` нельзя |
| `appendices` | массив | нет | приложения |
| `skip_last_page` | bool | нет | не добавлять последний лист с клятвой (по умолчанию `false`) |
| `keep_source_order` | bool | нет | не сортировать `sources`: номер записи = её целый `id` |
| `group_normative_first` | bool | нет | нормативные акты и стандарты — в начало списка литературы |

Строка вместо массива блоков — это один блок `text`: абзацы разделяются пустой
строкой, одиночный перевод строки — пробел, фрагмент в обратных кавычках
печатается моноширинным шрифтом.

## title_page

Те же ключи, что в `vkr-project.json` → `title_page` (SPEC 2). Раскладка — по
образцу титула ИМО 09.03.02 (`assets/titlepage-09-03-02-imo.docx`), титул
помещается на одну страницу A4.

| Ключ | Пример | Где на титуле |
|---|---|---|
| `university` | `Московский педагогический государственный университет` | четвёртая строка шапки в кавычках «…» (по умолчанию МПГУ) |
| `institute` | `Институт математики и информатики` | под автором, по центру |
| `department` | `кафедра информатики и методики обучения информатике` | блок заведующего: «Заведующий кафедрой / информатики и …» (слово «кафедра» срезается) |
| `program_code` | `09.03.02` | «Код и направление подготовки: 09.03.02. …» |
| `program_name` | `Информационные системы и технологии` | там же, после кода |
| `program_profile` | `Разработка игр и виртуальной реальности` | строка под «Направленность (профиль) образовательной программы:» |
| `work_type` | `Выпускная квалификационная работа` | «Выпускная квалификационная работа» и строка в скобках; `… (магистерская диссертация)` меняет скобки, по умолчанию «(бакалаврская работа)» |
| `author` | `Лебедева Анна Сергеевна` | ФИО полностью, полужирным справа |
| `authors` | `["ФИО 1", "ФИО 2"]` | коллективная ВКР: каждое ФИО отдельной строкой (вместо `author`) |
| `group` | `ИСТ-41` | «Группа ИСТ-41» под ФИО, справа |
| `supervisor` | `П.С. Кузнецов` | «Научный руководитель –», третья строка |
| `supervisor_title` | `доцент, канд. пед. наук` | вторая строка блока научного руководителя |
| `head_of_department` | `М.И. Орлов` | последняя строка блока «Допустить к защите / Заведующий кафедрой» |
| `head_title` | `д-р пед. наук, профессор` | строка над ФИО заведующего |
| `city` | `Москва` | «Москва – 2026 год» (по умолчанию Москва) |
| `year` | `2026` | там же (по умолчанию текущий год) |

Пустое поле, кроме `university`, `work_type`, `group`, `city` и `year`,
печатается маркером `[ЗАПОЛНИТЬ: …]` и попадает в предупреждения: такой титул
не пройдёт финальную проверку маркеров.

Ключи 6.32 читаются с предупреждением и переводятся в новые:

| Устаревший ключ | Новый ключ |
|---|---|
| `direction_code` | `program_code` |
| `direction_name` | `program_name` |
| `profile` | `program_profile` |
| `program` | `program_code + program_name` |
| `supervisor_name` | `supervisor` |
| `supervisor_position` | `supervisor_title` |
| `supervisor_degree` | `supervisor_title` |
| `head_name` | `head_of_department` |
| `head_degree` | `head_title` |

## Глава

| Ключ | Тип | Что делает |
|---|---|---|
| `title` | строка | название; префикс «Глава I.» срезается, номер ставится по порядку |
| `blocks` | массив блоков | текст главы до первого параграфа |
| `paragraphs` | массив | параграфы |
| `conclusion` | строка или массив блоков | «Выводы по главе N» в конце главы |

## Параграф

| Ключ | Тип | Что делает |
|---|---|---|
| `title` | строка | название; номер «1.2.» срезается и ставится заново по порядку |
| `text` | строка | текст параграфа (вместо `blocks`) |
| `blocks` | массив блоков | смешанное содержимое |

## Приложение

| Ключ | Тип | Что делает |
|---|---|---|
| `title` | строка, обязательно | заголовок по центру; в оглавлении «Приложение N. Заголовок» |
| `label` | строка | метка справа, по умолчанию «Приложение N» |
| `content` | строка | текст приложения (вместо `blocks`) |
| `blocks` | массив блоков | текст, списки, таблицы, листинги, рисунки |

## Блоки

| Тип | Ключи | Как печатается |
|---|---|---|
| `text` | `type`, `content` | абзацы TNR 14, отступ 1,25 см, по ширине |
| `list` | `type`, `items`, `ordered` | `List Paragraph` + автонумерация; каждый нумерованный список с 1; по ширине, висячий отступ |
| `table` | `type`, `number`, `title`, `headers`, `rows`, `source` | «Таблица N» справа, заголовок полужирный по центру, сетка, шрифт 12; строка «Источник: …» под таблицей |
| `listing` | `type`, `number`, `caption`, `code`, `language` | строки кода стилем `VKR Listing`, подпись «Листинг N — …» под кодом |
| `figure` | `type`, `number`, `caption`, `path`, `placeholder`, `width_cm` | изображение из `path` по центру (ширина ≤ 16,5 см или `width_cm`); без `path` или с `placeholder: true` — заглушка-маркер; подпись «Рисунок N — …» |

`number` необязателен: таблицы, рисунки и листинги нумеруются сквозь весь
документ. Ссылки в `text`, `items`, ячейках, `title`, `source` и подписях
пересчитываются; `code` листинга не меняется.

## Список литературы

- `sources` — записи реестра (`references/gost-citations.md`, «Реестр источников»).
  Генератор сортирует их по алфавиту, нумерует с 1 и переписывает ссылки `[@id]`
  и числовые `[N]` (N — целый `id` записи) во всех текстовых блоках. Ссылка на
  отсутствующий источник, повторяющийся `id` или запись без обязательных полей
  — ошибка (код 1).
- `keep_source_order: true` — порядок входа, номер = целый `id`; ссылки не
  переписываются; о непоследовательной нумерации и нарушении алфавита генератор
  предупреждает.
- `bibliography` — готовые строки, вставляются как есть (без номера в начале
  нумеруются 1, 2, …); `[@id]` в тексте при этом — ошибка.

## Стили результата

| Стиль | Что оформляет |
|---|---|
| `Normal` | основной текст: TNR 14, чёрный, 1,5, отступ 1,25 см, по ширине |
| `Heading 1` | Введение, Глава N, Заключение, Список использованной литературы: по центру, полужирный, без тематических шрифтов |
| `Heading 2` | параграфы «1.1. …» |
| `VKR Title` | абзацы титульного листа и последнего листа |
| `VKR Caption` | «Таблица N», заголовки таблиц, подписи рисунков и листингов, «Источник: …» |
| `VKR Listing` | строки кода (Consolas 11, одинарный интервал) |
| `VKR Bibliography` | записи списка литературы (отступ 1,25 см, номер — часть текста) |
| `VKR Appendix Label` | «Приложение N» справа |
| `VKR Appendix Title` | заголовок приложения по центру; содержит поле TC для оглавления |
| `List Paragraph` + numPr | пункты списков |
| `toc 1`, `toc 2`, `toc 3` | строки оглавления после обновления поля: без красной строки, влево |

Разделы начинаются с новой страницы через «с новой страницы» у первого абзаца
(`pageBreakBefore`), поэтому пустых страниц и двойных разрывов нет. Содержание —
поле `TOC \o "1-3" \h \z \u \f` с заглушкой внутри поля: после сборки обновите
поля в Word (Ctrl+A, F9).
