# Подключение к ИИ-системам

Технический адаптер навыка `vkr-mpgu` версии `6.33-production`. Методика, профиль
09.03.02, контрольные точки аудита, инициализация проекта и память одинаковы на
всех платформах; различается только то, что платформа умеет: запускать Python,
работать с файлами проекта и создавать отдельные контексты для аудиторов.
Установка — `INSTALL-RU.md`; сквозной путь с командами — `quickstart.md`.

## Что нужно от платформы

| Возможность | Зачем | Если её нет |
|---|---|---|
| Файлы проекта на диске | `drafts/*.md`, реестры, `final/vkr.docx`, `audit/`, `memory/` | проект передаётся ZIP-архивом; статус `filesystem_setup_pending` (`project-initialization.md`) |
| Запуск Python 3.9+ с `python-docx` | init, сборка, валидатор, аудит, doctor, память | агент готовит точные команды, пользователь запускает их локально и возвращает вывод; без вывода шаг не считается выполненным |
| Веб-поиск и открытие страниц | проверка источников (`source-verification.md`) | агент готовит запросы `verify_sources.py --queries`, пользователь проверяет сам |
| Отдельные контексты (субагенты) | независимые аудиторы `vkr_audit.py brief` | роли выполняются последовательно, run планируется с `--independence degraded_independence`, итог не выше `READY_FOR_SUPERVISOR_REVIEW` |

Служебные записи аудита (снимок, задачи, отчёты, замечания) пишет только
`vkr_audit.py`, память — `vkr_memory.py`. Ни на одной платформе поля
`audit/manifest.json` и канонических отчётов не заполняются вручную.

## Codex

Папка навыка: Windows — `%USERPROFILE%\.codex\skills\vkr-mpgu`; macOS/Linux —
`~/.codex/skills/vkr-mpgu`. Вызов в новой задаче: `$vkr-mpgu помоги начать ВКР с нуля`
или обычный запрос о ВКР. `agents/openai.yaml` отвечает за отображение навыка и не
меняет содержание `SKILL.md`.

Основной Codex-агент выполняет init, память, сборку и doctor в терминале. Для
аудита он получает задания `vkr_audit.py <PROJECT_DIR> brief --run <RUN_ID>` и
запускает по одному субагенту на задание через доступный механизм совместной
работы, при нехватке слотов — волнами. Аудитор получает только свой файл задания
и работает на чтение; его JSON-ответ основной агент сохраняет в файл вне `audit/`
и передаёт в `record`. Адресную перепроверку и слепую регрессию выполняют новые
субагенты с новыми `auditor_id`. Независимость: `isolated_contexts` (по умолчанию).

## Claude Code

Папка навыка: `~/.claude/skills/vkr-mpgu`. Вызов: `/vkr-mpgu помоги начать ВКР с нуля`
или обычный запрос о ВКР. Если в аккаунте платформы остался прежний `vkr-mpgu`,
синхронизированный в Claude Code и Claude Desktop, его нужно отключить
(`INSTALL-RU.md` → «Claude Code и Claude Desktop»), иначе одновременно загрузятся две версии.

Для независимого аудита основной агент запускает отдельного субагента (Task) на
каждое задание из `brief`; если можно ограничить инструменты субагента, аудитору
дают только чтение и поиск (Read, Grep, Glob, веб-поиск). Правило «исправляет
только основной агент» и запрет аудиторам менять файлы сохраняются. Независимость:
`isolated_contexts`; разные модели для спорных замечаний — `diverse_models`.

## Claude.ai, ChatGPT, Gemini и другие веб-чаты

Если платформа импортирует навыки (файл `.skill`), используй импорт
(`INSTALL-RU.md`). Иначе:

1. Помести содержимое `PORTABLE-PROMPT.md` в инструкции проекта.
2. Загрузи файлы знаний по канонической таблице `PORTABLE-PROMPT.md` → «Файлы
   для веб-систем» (обязательный набор включает всё, что `SKILL.md` велит
   прочитать в начале работы).
3. Скрипты `scripts/` и шаблоны `assets/` запускай локально, если веб-чат не
   исполняет Python с доступом к файлам проекта.

**Независимость в веб-чате.** Обычный веб-чат не создаёт субагентов, а записи
аудита делает только `vkr_audit.py` в среде с файлами проекта. Поэтому роли
аудиторов в том же чате выполняются последовательно и оформляются как
`degraded_independence`: doctor не выдаст выше `READY_FOR_SUPERVISOR_REVIEW`. Для
`READY_TO_SUBMIT` финальные волны проводятся в среде с отдельными контекстами
(Claude Code, Codex, агентный фреймворк). Отдельные новые чаты, открытые
пользователем вручную, полезны как дополнительная редактура, но их выводы
попадают в аудит только через `vkr_audit.py record` с честной отметкой
независимости.

**Продолжение в новой веб-сессии.** Приложи ZIP проекта или файлы из
`continuation_files` вывода `vkr_memory.py status` (`project-memory.md` →
«Завершение и передача в новый чат»): `vkr-state.md`, `vkr-project.json`,
`plan.md`, `sources.json`, `evidence/index.json`, `memory/handoff.json`,
`memory/handoff.md`, `memory/roadmap.md`, `memory/claims-register.json`,
`memory/artifact-index.json`, `audit/manifest.json`, `audit/findings.json`,
`audit/snapshot-inputs.json` и текущие `drafts/*.md`. Без `audit/manifest.json`
при активном аудите — причина остановки `RECOVERY_DATA_REQUIRED`; новый run поверх
потерянных задач не создаётся.

## API-агенты и локальные фреймворки

Передай `PORTABLE-PROMPT.md` как постоянную инструкцию, `SKILL.md` и файлы из
таблицы `PORTABLE-PROMPT.md` → «Файлы для веб-систем» — через файловый поиск или
базу знаний. Сопоставь возможности:

| Возможность | Ожидаемое действие |
|---|---|
| поиск | найти источник и вернуть его URL и реквизиты |
| открытие URL | прочитать конкретную страницу, DOI или PDF |
| чтение файла | получить текст Markdown, JSON или документа |
| запись файла | сохранить рабочий артефакт |
| Python | запустить скрипт из `scripts/` по абсолютному пути `<SKILL_DIR>` |
| инициализация | `init_vkr_project.py` по `project-initialization.md` |
| состояние | `vkr_memory.py status`, `vkr_audit.py next` |
| checkpoint | `vkr_memory.py record --event` |
| аудит | `vkr_audit.py plan/brief/record/close`; каждое задание — изолированный read-only вызов модели |
| preflight | `vkr_project_doctor.py --stage <стадия>` (`draft`, `prefinal`, `final`) |

Названия функций API могут быть любыми. Смысл операции должен совпадать с
инструкцией: аудиторы возвращают JSON-отчёты, основной агент применяет исправления
последовательно, новые задания проверяют новый снимок.

## Стоимость аудита

Одна задача аудита — один запуск субагента. Ориентиры из `continuous-audit.md` →
«Сколько это стоит»: финальный gate (primary + слепая волна) — **18** задач в
`balanced`, **24** в `strict`, **36** в `maximum`; вся проектная ВКР с
промежуточными точками — примерно **120–170**, **170–230** и **230–320** задач.
Минимальный путь к `READY_TO_SUBMIT` — финальные волны `balanced` плюс
перепроверки; пропуск промежуточных точек — осознанное решение пользователя,
записанное в state.

## Среда без инструментов

Используй навык как диалоговую методику. Если платформа умеет создавать
вложения, основной агент формирует и отдаёт проект одним ZIP. Иначе ассистент
готовит текст, JSON, запросы и команды, а пользователь выполняет файловые, сетевые
и Python-операции вручную. Результат считается полученным только после его
возврата в диалог. Независимым такой аудит не называется.

## Граница автоматизации

«Автоматически» означает: основной агент запускает нужную проверку при достижении
контрольной точки во время активной сессии, не спрашивая отдельную команду на
каждый gate. Скилл сам по себе не является фоновым файловым монитором. Если файл
изменён между сессиями, при следующем запуске `vkr_memory.py status` и
`vkr_audit.py snapshot` покажут изменения, а прежние волны к новому снимку не
относятся.
