# Проверка источников для ВКР

Этот файл — практическое руководство по проверке источников. Проверка обязательна в режиме `final`. В режиме `draft` — опционально, но ИИ-агент помечает непроверенные места `[ПРОВЕРИТЬ]`.

Результат проверки хранится в реестре `<PROJECT_DIR>/sources.json` (раздел
«Реестр источников» ниже); команды `verify_sources.py` — в разделе «Скрипт
`verify_sources.py`».

## 🔴 Обязательный workflow ИИ-агента в режиме `final`

**Главная угроза — галлюцинация источников.** ИИ-агент регулярно выдумывает правдоподобные, но несуществующие источники. Под дедлайном студент это **не** будет тщательно проверять. Поэтому ответственность лежит на ИИ-агенте.

**Протокол для ИИ-агента при каждом упоминании источника в режиме `final`:**

```
ПЕРЕД тем, как включить ссылку [@id] в текст работы:

1. ИИ-агент делает web_search по комбинации «фамилия автора + ключевые слова названия»
2. Если результат пустой или противоречивый → ИСТОЧНИК НЕ ВКЛЮЧАТЬ
   → Переформулировать тезис так, чтобы он не требовал ссылки,
     ИЛИ найти другую (подтверждённую) работу на ту же тему.
3. Если результат подтверждает — ИИ-агент проверяет год, издательство, страницы
4. Для прямых цитат (в кавычках) — web_fetch страницы, сверка текста слово в слово
5. Только после всех подтверждений — включать ссылку в текст и отмечать
   источник confirmed командой verify_sources.py --mark

ИСКЛЮЧЕНИЯ (не требуют web_search):
   - Классические работы, которые точно существуют (Выготский "Мышление и речь", 1934)
   - Актуальные нормативные документы (ФЗ, ГОСТы, приказы Минобрнауки)
   - Официальная документация (React docs, Unity docs, OpenXR spec)
Но даже для них — проверка выходных данных (год издания, редакция) обязательна.
```

**Это не рекомендация, а требование скилла.** Пользователь не должен сам проверять каждый источник под дедлайном — он не успеет и пропустит что-то. ИИ-агент делает это на лету во время генерации текста.

Нарушение этого правила = студент рискует дипломом.

## Почему это критично

**Фейковый источник в списке литературы — катастрофа для ВКР.** Нормоконтроль и научный руководитель проверяют выборочно. Если найдут один выдуманный источник — ставят под сомнение всю работу. Это не редкий случай: ИИ-инструменты регулярно «галлюцинируют» источники, придумывая правдоподобные названия, авторов и годы.

Проверить нужно:
1. **Существование работы** — есть ли она вообще?
2. **Правильность выходных данных** — автор, год, издательство, страницы
3. **Доступность URL/DOI** — работают ли ссылки?
4. **Отражение в тексте** — действительно ли автор писал то, что ему приписывается?

## Уровни проверки

### Уровень 1: Базовая проверка существования

**Для любого источника:**
- Ищи по полному названию в Google / Яндекс
- Ищи по паре «автор + ключевое слово названия»
- Если не находится — источник под подозрением

### Уровень 2: Проверка выходных данных

**Для книг:**
- Проверить в каталоге РНБ, РГБ или «ЛитРес», «Озон», «Лабиринт»
- Издательство действительно выпускало эту книгу в этом году?
- Номер ISBN (если доступен) соответствует изданию?

**Для статей:**
- Проверить журнал: существует ли, входит ли в ВАК, РИНЦ, Scopus?
- Номер и год соответствуют странам?
- У статьи есть DOI — прогнать по doi.org

### Уровень 3: Проверка на российских платформах

Для русскоязычных источников обязательно проверять на:

**eLibrary.ru (НЭБ)**
- Главная научная электронная библиотека России
- URL: https://elibrary.ru
- Содержит РИНЦ-индексируемые работы, ВАК-журналы
- Поиск: «Расширенный поиск» → автор + название
- Если работы нет на eLibrary — работы может и не быть вообще (для статей последних 15 лет)

**CyberLeninka (КиберЛенинка)**
- Открытая научная электронная библиотека
- URL: https://cyberleninka.ru
- Много русскоязычных научных статей в открытом доступе
- Можно найти статью целиком и свериться с цитатами

**РГБ (Российская государственная библиотека)**
- URL: https://search.rsl.ru
- Каталог для проверки книг, монографий, диссертаций

**disserCat**
- URL: https://www.dissercat.com
- Для проверки диссертаций и авторефератов

### Уровень 4: Проверка цитаты по тексту (для прямых цитат)

Если в ВКР стоит прямая цитата в кавычках — найти текст источника и проверить:
- Цитата точная (слово в слово)?
- Номер страницы совпадает?
- Контекст цитаты не искажён?

На CyberLeninka и elibrary многие тексты доступны в PDF — прогнать через поиск.

## Алгоритм проверки источника (в режиме `final`)

```
Для каждого источника реестра со статусом pending или suspicious:

1. Искать работу: web_search "автор + название"
   (готовые запросы: verify_sources.py --queries)
   → Если не находится — перестроить поиск (без подзаголовков, по ключевым словам)
   → Если по-прежнему не находится — отметить suspicious с заметкой и вернуться позже

2. Если найдена ссылка на источник:
   а. Для русскоязычных: искать на cyberleninka.ru или elibrary.ru
   б. Для англоязычных: scholar.google.com, doi.org
   в. web_fetch URL статьи/страницы
   г. Сверить: автор, год, журнал, страницы

3. Если в тексте ВКР есть прямая цитата из этого источника:
   а. Найти полный текст источника (если в открытом доступе)
   б. Проверить цитату слово в слово
   в. Проверить номер страницы

4. Записать результат в реестр (verify_sources.py --mark):
   confirmed  — работа существует, реквизиты сверены (method + url или note);
   suspicious — найдено частично или реквизиты не сходятся (note с причиной);
   rejected   — работа не существует или не годится для ВКР (note с причиной)

5. В конце — verify_sources.py --report: список suspicious и rejected отдать
   пользователю, чтобы он либо заменил источник, либо предоставил доказательства
```

## Красные флаги: источник скорее всего фейковый

ИИ склонен придумывать источники со следующими признаками:

- **Название слишком «идеально подходит»** к тезису, который подтверждает
- **Автор с таким ФИО не находится** в поиске научных публикаций
- **Журнал с таким названием существует**, но в указанный год/номер статьи такой не было
- **Страницы указаны «круглые»** (например, «С. 100-120», а не «С. 103-118»)
- **Издательство известное**, но книги такой нет в его каталоге
- **Год публикации — «удобный»** (часто последние 2-3 года, без конкретики в изданиях)

При любом из этих флагов — проверка обязательна.

## Особые случаи

### Устаревшие источники

Для большинства тем — источники **старше 15 лет** для подтверждения актуальных тезисов вызывают вопросы. Исключения:
- Фундаментальные работы (Выготский, Пиаже, Маслоу) — уместны всегда
- Классика в своей области (методологические работы) — уместны всегда
- Исторический раздел работы — уместны по теме

Для IT / педагогических технологий / Game Design / VR проверь, что основная
часть источников о текущих технологиях отражает современное состояние области.
Точный процент и период задаёт программа; фундаментальные и исторические
источники оцениваются отдельно.

### Источники без ISBN / DOI

Научно-практические конференции, методические рекомендации, региональные сборники часто не имеют ISBN/DOI. Для них проверка:
- Искать упоминание конференции в поисковиках
- Искать программу или книгу тезисов конференции
- Если источник доступен только по ссылке с конкретного сайта — обязательно указать URL и дату обращения

### Курсовые, дипломные, чужие ВКР

**В списке литературы ВКР их использовать НЕЛЬЗЯ.** Это не научные источники. Даже если они цитируются другими — ссылаться нужно на первоисточник, который цитирует студенческая работа.

### Википедия, форумы, блоги

- **Википедия** — не научный источник. Использовать только для первичной навигации, а ссылаться на источники из её раздела «Литература»
- **Форумы, блоги, посты в соцсетях** — в ВКР неприемлемо (за редкими исключениями, когда объект исследования — сами эти площадки)
- **Новостные сайты** — допустимы для освещения актуальных событий, но не как научные доказательства

### Иностранные источники

Для ВКР бакалавра **желательно 3-5 иностранных источников**, особенно в современных областях (IT, VR, Game Design).

Проверять на:
- **Google Scholar** (scholar.google.com)
- **Scopus** / **Web of Science** (если есть доступ)
- **ResearchGate** / **Academia.edu** — для препринтов и PDF
- **DOI.org** — для проверки существования работы по DOI

## Инструменты поиска (команды для ИИ-агента)

При работе с источниками используй:

```
# Поиск существования
web_search "автор + название"

# Поиск на CyberLeninka
web_search "название статьи site:cyberleninka.ru"

# Поиск на eLibrary
web_search "автор название site:elibrary.ru"

# Поиск на Google Scholar
web_search "название site:scholar.google.com"

# Для DOI
web_fetch "https://doi.org/10.xxxx/xxxxx"

# Для Википедии (как стартовая точка, но НЕ как источник)
web_fetch "https://ru.wikipedia.org/wiki/Тема"
```

## Реестр источников `<PROJECT_DIR>/sources.json`

Один реестр для `init`, `build_vkr.py`, `format_bibliography.py`,
`verify_sources.py`, doctor и `import_docx.py` — JSON-массив объектов. Поля
записи по типам источников — в [gost-citations.md](gost-citations.md), раздел
«Реестр источников `sources.json`».

```json
[
  {
    "id": "vygotsky1934",
    "type": "book",
    "authors": [{"last": "Выготский", "initials": "Л.С."}],
    "title": "Мышление и речь",
    "place": "М.",
    "publisher": "Соцэкгиз",
    "year": 1934,
    "pages": 324,
    "raw_text": "Выготский, Л.С. Мышление и речь. – М.: Соцэкгиз, 1934. – 324 с.",
    "status": "confirmed",
    "verification": {
      "checked_at": "2026-09-10T11:20:00.000+00:00",
      "method": "catalog",
      "url": "https://search.rsl.ru/",
      "note": "автор, год и издательство сверены по каталогу РГБ"
    }
  }
]
```

| Поле | Правило |
|---|---|
| `id` | строка `[A-Za-z0-9_.:-]+` или целое; уникален без учёта регистра. Черновики ссылаются `[@id]`, целые `id` допускают прежние ссылки `[3, с. 17]` |
| `status` | `pending` (по умолчанию), `confirmed`, `suspicious`, `rejected`. `verified` при чтении считается `confirmed`, но инструменты всегда пишут `confirmed` |
| `verification` | `{checked_at, method, url, note}`. У `confirmed` обязательны `method` (`catalog`, `doi`, `publisher`, `original`, `web_search`), `checked_at` в ISO 8601 и `url` или `note`. Пишет `verify_sources.py --mark`, время ставит скрипт |
| `raw_text` | исходная строка списка литературы (после `import_docx.py` или `--extract`); запись только с `raw_text` оформить по ГОСТ нельзя |

### Жизненный цикл статуса

```
pending ──проверка──► confirmed   (существование и реквизиты подтверждены)
   │                ► suspicious  (найдено частично: год, издательство, страницы не сходятся)
   │                ► rejected    (работа не существует или не годится для ВКР)
suspicious ──повторная проверка──► confirmed | rejected
rejected ──► ссылки [@id] убрать из черновиков, запись удалить или заменить другим источником
```

| Статус | Что делать | Что говорят инструменты |
|---|---|---|
| `pending` | проверить | `build_vkr.py`: предупреждение `SOURCES_NOT_CONFIRMED` для процитированных; doctor: `SOURCE_NOT_CONFIRMED` — предупреждение на prefinal, ошибка на final |
| `confirmed` | заполнить `verification` через `--mark` | без полного `verification`: `build_vkr.py` — предупреждение, doctor — `SOURCE_VERIFICATION_MISSING` (ошибка на final) |
| `suspicious` | перепроверить или заменить | как `pending` |
| `rejected` | убрать из текста и реестра | `build_vkr.py`: ошибка `SOURCE_REJECTED`, если источник процитирован; в список литературы не попадает |

Кроме статуса doctor на final требует уникальные `id` и структурированные записи
(`SOURCE_UNSTRUCTURED` для записи только с `raw_text`); `build_vkr.py` выдаёт
ошибку `SOURCE_UNSTRUCTURED`, если такую запись цитируют.

## Скрипт `verify_sources.py`

Скрипт извлекает список литературы из DOCX, строит поисковые запросы, записывает
результат проверки в реестр и сводит статусы. **Сам он в интернет не
обращается**: запросы выполняет ИИ-агент через доступный `web_search` /
`web_fetch`.

```bash
python <SKILL_DIR>/scripts/verify_sources.py --extract <PROJECT_DIR>/final/vkr.docx -o <PROJECT_DIR>/audit/sources-extracted.json
python <SKILL_DIR>/scripts/verify_sources.py --queries <PROJECT_DIR>/sources.json
python <SKILL_DIR>/scripts/verify_sources.py --mark <PROJECT_DIR>/sources.json --id vygotsky1934 --status confirmed --method catalog --url https://search.rsl.ru/ --note "год и издательство совпали"
python <SKILL_DIR>/scripts/verify_sources.py --report <PROJECT_DIR>/sources.json
```

Во всех режимах `--json` печатает только JSON; для `--report` и `--queries`
`-o FILE` дополнительно пишет JSON-отчёт в файл (UTF-8, каталоги создаются).
Внутрь каталога скилла скрипт не пишет ни в одном режиме (код 2).
В PowerShell с OEM-кодировкой консоли читай JSON из файла `-o`, а не перехваченный
вывод (подробнее — [analyzers-cli.md](analyzers-cli.md)).

### `--extract`: инвентарь списка литературы из DOCX

- Раздел ищется по заголовку: «Список использованной литературы», «Список
  использованных источников», «Список литературы», «Библиографический список»,
  «Литература», «Список использованной литературы и источников» — в любом
  регистре, с двоеточием или без. Строки оглавления (стили TOC, поле TOC,
  sdt-оглавление, строки «Название<TAB>34») заголовком не считаются.
- Раздел заканчивается на следующем заголовке (Heading 1, названия разделов в
  стиле Heading 2+), «Приложение N», «Приложения», последнем листе
  («Выпускная квалификационная работа» после текста) или таблице с клятвой.
  Подзаголовок уровня 2 и ниже внутри списка пропускается с предупреждением.
- Запись — абзац с номером в тексте («1.», «1)», «[1]»), с автонумерацией Word
  (numPr, стиль List Number) или со стилем `VKR Bibliography`. Абзац без номера
  приклеивается к предыдущей записи, если это очевидное продолжение («– URL: …»,
  строчная буква, висящий знак в конце записи); иначе он попадает в `warnings`,
  а не в записи.
- Результат — массив `{"id": номер, "raw_text": …, "status": "pending", "hints": {…}}`.
  Повторяющийся номер получает следующий свободный `id` с предупреждением.
- Без `-o` файл пишется в `<PROJECT_DIR>/audit/sources-extracted.json` (если выше
  DOCX найден `vkr-project.json`), иначе рядом с DOCX.
- Существующий файл перезаписывается только с `--force`. **Реестр
  `sources.json` со структурированными или уже проверенными записями не
  перезаписывается никогда**, даже с `--force`: укажи другой путь.
- 0 записей — код 1 с объяснением (заголовок не найден или в разделе нет
  нумерованных абзацев), файл не создаётся.

### Перенос извлечённых записей в реестр

`audit/sources-extracted.json` — инвентарь текста DOCX, `sources.json` —
реестр проекта. Если проект создан через `import_docx.py`, реестр уже содержит
записи `{"id": N, "raw_text": …, "status": "pending"}` с теми же номерами;
инвентарь нужен для сверки после правок в Word. Повторный `import_docx.py --force`
на проекте со структурированным или проверенным реестром пишет инвентарь в тот же
`audit/sources-extracted.json`, а реестр не трогает: номера `[N]` новых черновиков
относятся к инвентарю, их сверяют с реестром по шагам ниже.

1. Сопоставь записи инвентаря с реестром по `id` (номеру в списке) и `raw_text`.
   Новую запись добавь в `sources.json`, сохранив `raw_text`.
2. Разложи `raw_text` на поля по схеме [gost-citations.md](gost-citations.md)
   («Реестр источников `sources.json`»): `type`, `authors`, `title`, выходные
   данные, `url`/`doi`. Подсказки `hints` (автор, заглавие, год, DOI, ISBN, URL)
   — только эвристика, сверяй их с оригиналом.
3. Не меняй `id` записей, на которые черновики ссылаются числами `[N]`; для новых
   источников используй строковый `id` и ссылку `[@id]`.
4. Проверь источник (запросы — `--queries`) и запиши итог через `--mark`:
   `confirmed` с `--method` и `--url` или `--note`; `suspicious` или `rejected` —
   с `--note` о причине.
5. `--report` должен закончиться кодом 0: все записи `confirmed` с полным
   `verification`, без ошибок реестра.

### `--queries`: поисковые запросы

Запросы строятся для записей `pending`, `suspicious`, записей без статуса и
`confirmed` без полного `verification` (`rejected` и полностью подтверждённые
пропускаются). Реестр без `id` поддерживается: запись обозначается позицией
`[#N]`. Точная фраза заглавия очищается от «[Электронный ресурс]», «[Текст]»,
«/ авторы», «// издание», «: электронный …», «: дис. …»; автор, год, DOI, ISBN и
URL идут отдельными запросами. Для русских статей и книг добавляются
eLibrary и КиберЛенинка, для диссертаций — disserCat, для нормативных документов
— запрос по номеру или обозначению.

### `--mark`: запись результата проверки

```bash
python <SKILL_DIR>/scripts/verify_sources.py --mark <PROJECT_DIR>/sources.json --id ID --status confirmed --method doi --url https://doi.org/10.xxxx/xxxxx
python <SKILL_DIR>/scripts/verify_sources.py --mark <PROJECT_DIR>/sources.json --id ID --status suspicious --note "год издания 2018, а не 2020"
python <SKILL_DIR>/scripts/verify_sources.py --mark <PROJECT_DIR>/sources.json --index 7 --status rejected --note "работа не найдена в РГБ и eLibrary"
```

Скрипт пишет `status` (`verified` → `confirmed`) и `verification` с текущим
`checked_at`; `--status pending` снимает `verification`. Для `confirmed`
обязательны `--method` и `--url` или `--note`, для `suspicious` и `rejected` —
`--note`. `--index N` — позиция записи, если у неё нет `id`.

### `--report`: сводка

Печатает число записей по статусам и **перечень** `suspicious`, `pending`,
`rejected` и записей с неизвестным статусом с заметками
(`verification.note`, `verification.url`), отдельно — `confirmed` без полного
`verification` с указанием, чего не хватает, и ошибки реестра (нет `id`,
повторяющийся или некорректный `id`, запись не объект).

### Коды выхода

| Код | `--extract` | `--report` | `--queries` | `--mark` |
|---|---|---|---|---|
| 0 | записи извлечены | все источники `confirmed` с полным `verification` | запросы построены | запись обновлена |
| 1 | 0 записей | есть `pending`/`suspicious`/`rejected`/неизвестный статус, `confirmed` без `verification`, ошибки реестра или реестр пуст | реестр пуст | — |
| 2 | нет файла, повреждённый DOCX, нет python-docx, выходной файл существует без `--force` или защищён, ошибка записи | нет файла, некорректный JSON или не массив | как в `--report` | неверные аргументы, запись не найдена, `id` повторяется |

## Что делать, если источник не подтверждается

1. **Не паниковать.** Возможно, работа существует, но её сложно найти (редкое издание, региональный сборник, старая работа).

2. **Расширить поиск:**
   - По ключевым словам из названия
   - По другим работам этого автора
   - Через РГБ / РНБ каталог

3. **Если всё равно не находится:**
   - Попросить пользователя прислать подтверждение (фото обложки, скан страницы, PDF)
   - Если подтверждения нет — **заменить источник** на проверенный
   - Или **переформулировать тезис в тексте** так, чтобы ссылка не требовалась

4. **Никогда не «оставлять как есть» с отметкой «потом проверит научрук».** Научрук и проверит, и отчислит.

## Краткий чек-лист источника

Перед включением в список литературы:

- [ ] Название совпадает с реальной работой
- [ ] Автор подтверждён (существует, писал в этой области)
- [ ] Год публикации совпадает с реальным изданием
- [ ] Издательство / журнал реальны
- [ ] Страницы (если статья) указаны реальные
- [ ] URL (если электронный) работает, ведёт на нужный ресурс
- [ ] Дата обращения указана (для электронных)
- [ ] DOI (если есть) разрешается
- [ ] Прямая цитата (если есть) сверена с текстом
- [ ] Номер страницы цитаты верный
- [ ] В реестре `status: confirmed` и полный `verification` (`verify_sources.py --report` → код 0)
