# Структура ВКР в формате проекта (40–50 стр.)

Этот файл описывает структуру ВКР в формате проекта для МПГУ. Для обычной теоретической ВКР — см. `structure-regular.md`.

## Педагогическое обоснование проекта для 09.03.02

Профиль `mpgu-09-project` основан на разделе о ВКР в формате проекта документа
`assets/methodology-09-03-02-2024.docx` (происхождение — `methodology-mpgu.md`).
Он прямо описывает **образовательный продукт**, его целевую аудиторию,
методические основания и пилотный запуск. Для этого профиля образовательная
рамка и три главы обязательны.

**Во введении:** образовательная проблема, целевая аудитория, цель, задачи,
методологические основания, методы, экспериментальная база и ожидаемый эффект.

**В Главе II:** образовательная среда, потребности обучающихся или преподавателей,
состояние проблемы и сравнение с альтернативными образовательными решениями.

**В Главе III:** содержание и логика продукта, дизайн пилотного запуска, результаты
тестового внедрения, корректировки и разработанные материалы или их образцы.
Техническая архитектура, код и тестирование дополняют эти элементы.

Если исходный игровой или инженерный продукт имеет реальное применение в
обучении, опиши именно это применение и проверяй его на соответствующей целевой
аудитории. Если образовательного применения нет, не придумывай его: до написания
согласуй обычный формат ВКР или иной конечный продукт с научным руководителем и
руководителем программы.

### Где проводится пилот

- образовательная организация: школа, СПО, вуз;
- организация, связанная с обучением и развитием персонала;
- образовательная онлайн-платформа или программа ДПО;
- частная практика, например репетиторство, только по согласованию; для этого
  случая методичка требует не менее **5 участников**.

Для первых трёх вариантов методичка не задаёт числовой минимум. Размер выборки
обосновывается дизайном пилота и согласуется с научным руководителем.

На intake-интервью зафиксируй профиль `mpgu-09-project` (в `intake.json` и
`vkr-project.json` — ключ `profile`; `validation_profile: mpgu-09-project` —
допустимый алиас), реальную образовательную целевую аудиторию, базу пилота и
источник требований.

## Что такое ВКР-проект

ВКР в формате проекта — это научно обоснованное решение практической задачи в виде **готового продукта деятельности**. Для `mpgu-09-project` работа включает **реальный образовательный продукт** (методика, курс, приложение, игра, VR-продукт и т.д.), его пилотирование и описание процесса. Иной формат применяется только по согласованному плану.

Базовая методичка описывает четыре этапа:
1. **Анализ** — требования к продукту, ЦА, проблема, конкурентный анализ
2. **Проектирование** — структура продукта, логика, гипотезы
3. **Пилотирование** — тестовый запуск
4. **Разработка** — наполнение (задания, лекции, контент и т.д.)

Для частной образовательной практики методичка указывает минимум **5 человек**.
Для других типов пилота размер выборки определяется профилем и методом.

## Общий состав работы (в порядке вшивки)

1. Титульный лист (не нумеруется)
2. Аннотация (стр. 2)
3. Содержание (стр. 3)
4. **Введение** (~4-5 стр.)
5. **Глава I. Теоретическая часть** (~10–12 стр.)
6. **Глава II. Аналитическая часть** (~10–12 стр.)
7. **Глава III. Собственно проектная часть** (~12–15 стр.)
8. **Заключение** (~3 стр.)
9. Список литературы
10. Приложения (обычно много — разработанные материалы, примеры, фото пилотирования)
11. Клятва
12. **Справка о внедрении проекта**, если она требуется кафедрой

**Общий объём текстовой части: 40-50 стр.** без учёта приложений и списка литературы.

> Это ориентир для планирования объёма глав. **В аннотацию идёт полный объём
> файла по счётчику Word** (его печатает `update_docx_fields.py`), при

## Введение (подробно для проектной ВКР)

Базовые элементы введения; обязательный состав уточняется по программе:

### 1. Актуальность
Зачем нужен проект? Какую реальную проблему/потребность решает?

### 2. Проблема
Какая конкретная проблема решается проектом? Сформулировать в виде противоречия:
- «С одной стороны, [существует потребность/требование X]...»
- «С другой стороны, [текущие решения недостаточны / не учитывают Y]...»

### 3. Степень разработанности / Конкурентный анализ
Обзор существующих решений. Как проблему решали до этого? Что есть на рынке? Что из этого работает и что нет? (Это основа для Главы II.)

### 4. Цель проекта
Желаемый результат, который планируется достичь. Не «изучить» и не «рассмотреть» — а **что будет создано и для кого**.

Пример: «Разработать обучающее VR-приложение для учащихся 7-9 классов, направленное на формирование пространственного мышления при изучении стереометрии.»

### 5. Задачи проекта
3-5 задач. По смыслу **пересекаются с параграфами** работы.

Типовой набор:
1. Проанализировать теоретические основы использования X в Y.
2. Изучить целевую аудиторию и её потребности.
3. Проанализировать существующие решения / конкурентов.
4. Спроектировать и разработать продукт.
5. Провести пилотный запуск и оценить эффективность.

### 6. Гипотеза
Предположение о результате: «Использование разработанного продукта приведёт к повышению Z на N%» или «Учащиеся, прошедшие разработанный курс, покажут более высокие результаты по X».

### 7. Новизна (для бакалавров опционально, но усиливает)
Что принципиально нового в проекте? Новый подход, технология, комбинация методов, целевая аудитория?

### 8. Теоретическая и/или практическая значимость
- **Теоретическая:** вклад в научную дисциплину (обычно скромный для бакалаврского проекта)
- **Практическая:** кто и как может использовать проект? Где он может тиражироваться?

### 9. Методологические основы
Ключевые концепции и теории, на которых построен проект.

Пример: «Проект опирается на деятельностный подход (Л.С. Выготский), теорию когнитивной нагрузки Дж. Свеллера и принципы геймификации образования (K. Werbach).»

### 10. Методы
Способы, инструменты, алгоритмы достижения цели.

Пример: «В работе использованы: анализ литературы и конкурентов, метод проектирования образовательных продуктов ADDIE, метод пользовательского тестирования (usability testing), анкетирование, методы качественной обработки данных.»

### 11. Экспериментальная база
Где, как и с кем проводилось пилотное исследование?

Пример формулировки (база, период и число участников — только из реальных данных пилота): «Пилотирование проводилось на базе ГБОУ Школа № … г. Москвы в период сентябрь-ноябрь 2025 г. В пилотном запуске приняли участие … учащихся 8-х классов.»

### 12. Структура ВКР
Объём, количество глав и параграфов, приложения.

### Порядок изложения элементов введения — выбор из двух вариантов *(v6.26-friends)*

⚠️ **При friend-sharing:** разные пользователи скилла должны выбирать **разный** порядок элементов введения. Поле в state-файле: `structural_choices.intro_order` ∈ {`standard`, `methodology-first`}. Выбор через `user_seed`:

1. Актуальность

3. Степень разработанности / конкурентный анализ
4. Объект исследования
5. Предмет исследования
6. Цель проекта
7. Задачи проекта

**Вариант 2 — `methodology-first` (методология выносится раньше):**

6. Методы
7. Степень разработанности / конкурентный анализ (после методологии — она задаёт оптику обзора)

10. Гипотеза
11. Новизна
12. Теоретическая и практическая значимость

14. Структура работы

**Оба варианта формально соответствуют методичке МПГУ** — методичка перечисляет элементы, которые рекомендуется раскрыть, но не задаёт их строгий порядок. Разный порядок изложения у разных студентов снижает структурный отпечаток группы пользователей одного скилла.

**Семантически** оба варианта корректны:
- `standard` — индуктивный путь: «есть проблема → как её решали → что мы делаем → как»
- `methodology-first` — дедуктивный путь: «есть проблема → теоретическая рамка → анализ через эту рамку → что мы делаем»

Для научного руководителя оба варианта читаются нормально; типовая ВКР МПГУ может быть в любом из них.

## Глава I. Теоретическая часть

Содержит **изучение специальной литературы и нормативных документов**. Методологическая основа проекта.

### Примеры структуры параграфов

**Вариант А:**
- 1.1. Характеристика современного состояния исследуемой проблемы
- 1.2. Методологические подходы к решению проблемы. Выбор методов анализа и проектирования
- 1.3. Определение пути (путей) решения проблемы

**Вариант Б (под разработку образовательного продукта):**
- 1.1. Теоретические основы [предметной области] в контексте исследуемой проблемы
- 1.2. Психолого-педагогические особенности [возрастной группы / ЦА]
- 1.3. Обзор технологий / подходов, применимых для решения задачи

### Важно

- Блок **«Выводы по главе I»** в конце (3–5 тезисов) добавляется, если он предусмотрен утверждённым планом или указан научным руководителем; сама методичка 09.03.02 отдельного формального требования к таким блокам не содержит. В черновике — заголовок `## Выводы по главе`, номер главы ставит сборка
- Ориентир: 15 и более ссылок на разные источники; формальный минимум уточняется у кафедры
- Баланс: классика + современные работы (последние 5-7 лет)
- Для IT/геймдизайн/VR тематики полезны иностранные первичные источники и официальная документация; обязательность задаёт кафедра

## Глава II. Аналитическая часть

Анализ **реального состояния исследуемого объекта**. Основа для проектных решений в Главе III.

### Типовая структура параграфов

- **2.1. Краткая характеристика исследуемого объекта**
  - Что за организация/среда/контекст, в котором будет работать продукт?

- **2.2. Изучение целевой аудитории**
  - Кто пользователь? Возраст, уровень подготовки, мотивации, паттерны поведения
  - Результаты опроса / интервью / наблюдения (если проводилось)

- **2.3. Анализ состояния исследуемой проблемы в организации**
  - Как сейчас решается проблема? Что работает, что нет? Какие ресурсы есть?

- **2.4. Анализ конкурентов и альтернативных решений**
  - Таблица или матрица сравнения существующих продуктов
  - Критерии: функциональность, UX, стоимость, доступность
  - Вывод: свободная ниша / дифференциация нашего проекта

### Важно
- Это **эмпирическая** часть — нужны **свои данные**: анкеты, интервью, наблюдения, таблицы анализа
- Таблицы и графики нужны там, где они лучше текста показывают сравнение или результаты; декоративные визуализации не добавлять
- Если план предусматривает выводы по главе, здесь они особенно важны: они обосновывают решения в Главе III

## Глава III. Собственно проектная часть

### Структура — две ветви

**Ветвь А — каноничная (по методичке МПГУ, безопасна всегда).** Подходит для большинства проектов. Четыре параграфа:

- **3.1. Содержание проекта**
  - Формулирование целей программы/курса/проекта
  - Описание структуры и логики продукта
  - Формат (онлайн/офлайн/смешанный), длительность, объём
  - Ожидаемые результаты обучения

- **3.2. Дизайн пилотного запуска**
  - Выборка: кто, сколько, почему эти
  - Период, сроки, этапы
  - Инструменты оценки (пре-тест, пост-тест, анкеты удовлетворённости)
  - Гипотезы для проверки

- **3.3. Анализ результатов тестового внедрения**
  - Конкретные цифры: сколько, на сколько, у кого
  - Качественные выводы: что понравилось, что нет, что неочевидно
  - Сравнение с ожиданиями из 3.1

- **3.4. Разработанные учебные материалы (или их образцы)**
  - Описание того, что вошло в конечный продукт
  - Ссылки на приложения, где сами материалы
  - Рекомендации по применению и тиражированию

---

**Ветвь Б — расширенная для сложных IT-проектов (согласовать с научруком!).** Применяется, когда у пользователя реальный инженерный продукт с нетривиальной архитектурой, требующий отдельного технического описания. По сути — Ветвь А с разнесённым параграфом 3.1 на техническую детализацию:

- **3.1. Общая архитектура решения** — схема компонентов, стек технологий, взаимодействие подсистем
- **3.2. Ключевая функциональная подсистема** — ядро / движок / центральный компонент продукта
- **3.3. Дополнительные компоненты и интеграции** — веб-платформа / админ-панель / внешние API
- **3.4. Инфраструктура, безопасность, персональные данные** — хостинг, 152-ФЗ, логирование
- **3.5. Дизайн пилотного запуска** — как в Ветви А п. 3.2
- **3.6. Результаты опытной эксплуатации** — как в Ветви А п. 3.3
- **3.7. Направления дальнейшей доработки** — roadmap, ограничения текущего решения

**Правило выбора:**
- **Ветвь А (по умолчанию)** — всегда безопасна, соответствует методичке, меньше риск вопросов у комиссии «почему не по методичке». Подходит для большинства проектов.
- **Ветвь Б** разворачивает реализацию в 6–7 параграфов. Применять, если продукт действительно требует такого уровня детализации и план согласован с научным руководителем.

Подробнее о выборе ветви — см. `writing-workflow.md` Этап 1.


### Примеры конечных продуктов

Методичка МПГУ допускает широкий диапазон:

**Дидактические материалы:**
- Цифровой (электронный) образовательный ресурс
- Программа курса внеурочной деятельности с методическими и дидактическими материалами
- Банк диагностических заданий

**Для Game Design / VR (актуально для специальности):**
- VR-симуляция или VR-тренажёр
- Обучающая игра или серия уроков с применением игровых технологий
- Интерактивный учебный контент
- Прототип образовательного приложения

**Иные типы** (по согласованию с научным руководителем и руководителем программы).

### Где может быть реализован проект

- **Образовательные организации** — школы, колледжи, вузы
- **Не-образовательные организации** — отделы обучения и развития персонала, онлайн-платформы дополнительного образования
- **Частная практика** — репетиторство, курсы (по согласованию; минимум 5 человек для пилотирования)

## Заключение (для ВКР-проекта)

**Правила те же, что и для обычной ВКР:**
- НЕТ ссылок и цитат
- Подведение итогов по задачам введения
- Проверка гипотезы
- Основные результаты (пронумеровано 3-5)
- Перспективы

**Специфика проектной ВКР:**
- Обязательно сказать о **продукте** — что конкретно разработано
- Указать о **пилотном запуске** и его результатах
- Отметить **ограничения** (малая выборка, краткость периода и т.п.)
- Перспективы = куда проект может развиваться (масштабирование, новые модули, доработки)

## Чек-лист структуры для ВКР-проекта

- [ ] Все 4 этапа проекта пройдены: анализ / проектирование / пилотирование / разработка
- [ ] Во введении раскрыты рекомендованные методичкой элементы либо зафиксированы согласованные исключения
- [ ] Задачи введения отражены в параграфах работы
- [ ] Ровно три главы: «Глава I. …», «Глава II. …», «Глава III. …»
- [ ] В Главе II есть **свои** данные (опросы, интервью, анализ конкурентов)
- [ ] В Главе III описан продукт + пилот + результаты (результаты — только по реальным данным из `evidence/pilot/`)
- [ ] Размер выборки обоснован; для частной образовательной практики — **минимум 5 человек** по базовой методичке
- [ ] Есть сам продукт (или образцы) — в приложениях или по ссылке
- [ ] Если план предусматривает выводы по главам — в конце каждой главы есть «Выводы по главе N»
- [ ] Заключение без ссылок и цитат
- [ ] Последний лист ВКР (клятва) подписан живой ручкой
- [ ] Подписана **справка о внедрении** (для проектной ВКР — уточни обязательность у научрука)
- [ ] **Три вкладыша после клятвы** (по методичке МПГУ):
  - [ ] Отзыв научного руководителя (готовит научрук)
  - [ ] Разрешение на размещение в информационной системе МПГУ (`assets/permission-template.docx`, 2 страницы, подписано живой ручкой; при коллективном проекте — от каждого участника)
  - [ ] Справка о результатах проверки в «Антиплагиат.Вуз» (с указанным процентом оригинальности)
