# Детали оформления .docx для МПГУ

Параметры, по которым `scripts/build_vkr.py` (через рендерер
`scripts/create_vkr_docx.py`) собирает `final/vkr.docx` из черновиков. Что
прямо требует методичка (`assets/methodology-09-03-02-2024.docx`), отмечено
«методичка»; остальное — принятые в скилле решения там, где методичка молчит.

## Параметры страницы

| Параметр | Значение (мм) | Значение в twips |
|----------|---------------|------------------|
| Верхнее поле | 20 (методичка) | 1134 |
| Нижнее поле | 20 (методичка) | 1134 |
| Левое поле | **35** (методичка) | 1985 |
| Правое поле | 10 (методичка) | 567 |
| Формат | A4 | — |
| Ориентация | Портретная | — |

## Параметры шрифта

| Параметр | Значение |
|----------|----------|
| Семейство | Times New Roman (методичка) |
| Размер основного текста | 14 pt (методичка) |
| Размер заголовков | 14 pt, полужирный |
| Размер текста таблиц | 12 pt (методичка допускает меньший шрифт в таблицах) |
| Цвет | чёрный (методичка) |
| Заголовки | стили `Heading 1`/`Heading 2` без тематических шрифтов и цветов |

## Параметры абзаца основного текста

| Параметр | Значение |
|----------|----------|
| Межстрочный интервал | 1,5 (методичка) |
| Выравнивание | по ширине (методичка) |
| Абзацный отступ (красная строка) | 1,25 см (методичка) |
| Интервал перед и после | 0 («лишние пробелы между абзацами отсутствуют») |
| Запрет висячих строк | включён |

## Заголовки

Методичка: главы нумеруются римскими цифрами, параграфы — «1.1.», заголовки с
заглавной буквы без точки в конце, расстояние между заголовком и текстом 15 мм,
каждую главу рекомендуется начинать с нового листа.

### Глава («Глава I. Название главы»)

- Стиль `Heading 1`: 14 pt, полужирный, по центру, без красной строки
- Интервал перед 0 (глава с новой страницы), после — 42 pt (≈15 мм)
- Номер ставит сборка по имени файла `chapter-N.md`; префикс «Глава I.» в
  черновике не дублируется

### Параграф («1.1. Название»)

- Стиль `Heading 2`: 14 pt, полужирный, влево с отступом 1,25 см
- Интервал перед 18 pt, после 42 pt
- Номер «1.1.» ставит сборка по порядку

### Выводы по главе

«Выводы по главе I» — полужирный абзац по центру в конце главы (не в
оглавлении). Методичка отдельного раздела выводов не требует: их наличие
определяют план и научный руководитель.

### Разделы

- «Введение», «Заключение», «Список использованной литературы» — `Heading 1`,
  по центру, входят в содержание.
- «Аннотация» и «Содержание» — полужирные заголовки по центру без стиля
  заголовка: в содержание они не входят.
- Каждый раздел начинается с новой страницы через свойство абзаца «с новой
  страницы» (`pageBreakBefore`), а не через символ разрыва: пустых страниц и
  двойных разрывов нет, в том числе в конце документа без последнего листа.

## Содержание (оглавление)

Методичка рекомендует формировать содержание автоматически. Сборка вставляет
поле `TOC \o "1-3" \h \z \u \f` с заглушкой внутри поля; поля обновляет
`update_docx_fields.py` (через Word) или вручную в Word (Ctrl+A, F9). Строки оглавления — стили `toc 1`
(без отступа) и `toc 2` (отступ 0,5 см), без красной строки, влево; перенос
длинной строки не уходит левее первой строки.

## Нумерация страниц

- Арабские цифры, 14 pt, внизу по центру (методичка: «внизу листа посередине или справа»)
- На титульном листе номер не отображается, но титул считается страницей 1 (методичка)
- Нумерация видна с аннотации (страница 2)

**Разрыв раздела в Word** (например, для альбомной таблицы в приложении): Word
переносит в новый раздел настройки предыдущего — «Особый колонтитул для первой
страницы» (у титула он включён) и, если задано, начало нумерации с 1. В новом
разделе сними флажок «Особый колонтитул для первой страницы» и в «Формат номеров
страниц» выбери «продолжить». Иначе первая страница раздела останется без номера
(ошибка валидатора) или нумерация начнётся заново (ошибка для `mpgu-*`,
предупреждение для `generic`).

## Таблицы

- «Таблица N» — в правом верхнем углу над заголовком, без точки после номера (методичка)
- Заголовок — над таблицей, по центру, полужирный, строчными кроме первой прописной, без точки (методичка)
- Шрифт внутри 12 pt, одинарный интервал (методичка допускает)
- Все границы; строка заголовков повторяется на следующей странице
- Заимствованная таблица — со ссылкой: строка «Источник: …» под таблицей (методичка требует ссылку)
- Номер сквозной; в черновике — строка `Таблица: Название` перед pipe-таблицей

## Рисунки

Методичка оформление рисунков не описывает. В скилле принято:

- Рисунок по центру, ширина не больше области текста (165 мм)
- Подпись **под рисунком** по центру: «Рисунок 1 — Название рисунка», 14 pt, без точки
- Номер сквозной; в тексте — «…показано на рисунке 1»
- В черновике — `![Название](evidence/figures/файл.png)`; пустой путь — заглушка-маркер

## Списки

- Стиль `List Paragraph` с автоматической нумерацией Word (numPr), 14 pt, интервал 1,5
- Выравнивание по ширине, без красной строки: номер на 1,25 см, текст и
  переносы строк — с висячим отступом
- Каждый нумерованный список начинается с 1 (отдельная нумерация на список)
- Маркер маркированного списка — «–»

## Листинги кода

Методичка листинги не описывает. В скилле принято:

- Стиль `VKR Listing`: Consolas 11 pt, одинарный интервал, отступ слева 1 см, без красной строки
- Подпись **под кодом** по центру курсивом 12 pt: «Листинг 1 — Название»
- В черновике — строка `Листинг: Название` перед fenced-блоком (`references/drafts-format.md`)

## Список литературы

- Заголовок «Список использованной литературы» (`Heading 1`, в содержании)
- Порядок — алфавитный (методичка: «Список составляется в алфавитном порядке»),
  правило сортировки — `references/gost-citations.md`
- Сквозная нумерация «1. Иванов, А.Б. …»; номер — часть текста записи
- Стиль `VKR Bibliography`: абзацный отступ 1,25 см (как у основного текста),
  по ширине, интервал 1,5; висячий отступ не используется
- Записи и номера ссылок `[N, с. …]` в тексте формирует `build_vkr.py`

## Приложения

- После списка литературы, каждое с новой страницы (методичка)
- «Приложение N» в правом верхнем углу (методичка) — стиль `VKR Appendix Label`, полужирный
- Заголовок приложения по центру, с прописной буквы, отдельной строкой (методичка) —
  стиль `VKR Appendix Title`
- В содержании приложение выглядит как «Приложение N. Название»: заголовок содержит
  поле TC, которое Word учитывает при обновлении содержания (ключ `\f`)
- Внутри — текст, списки, таблицы, листинги, рисунки

## Титульный лист

Раскладка — по образцу `assets/titlepage-09-03-02-imo.docx`. Методичка отсылает к
образцам, публикуемым институтом ежегодно: перед сдачей сверь титул с актуальным
постом кафедры. Все абзацы титула — стиль `VKR Title` (одинарный интервал, без
красной строки); титул помещается на одну страницу A4. Данные — из
`vkr-project.json` → `title_page`:

| Строка титула | Ключ `title_page` |
|---|---|
| «Министерство просвещения Российской Федерации» … «Московский педагогический государственный университет» | `university` (последняя строка шапки) |
| ФИО автора — полужирным справа | `author` (или `authors` для коллективной ВКР) |
| «Группа …» справа | `group` |
| Институт — по центру | `institute` |
| Тема — полужирным по центру | `topic` в `vkr-project.json` |
| «Код и направление подготовки: 09.03.02. Информационные системы и технологии» | `program_code`, `program_name` |
| «Направленность (профиль) образовательной программы:» и профиль | `program_profile` |
| «Выпускная квалификационная работа» / «(бакалаврская работа)» | `work_type` |
| «Научный руководитель –», должность и степень, И.О. Фамилия | `supervisor_title`, `supervisor` |
| «Допустить к защите», «Заведующий кафедрой», кафедра, линия подписи, степень, И.О. Фамилия | `department`, `head_title`, `head_of_department` |
| «Проверка на объем заимствований: _______% авторского текста» | — |
| «Москва – 2026 год» | `city`, `year` |

Пустое поле печатается маркером `[ЗАПОЛНИТЬ: …]` — финальная проверка маркеров его
не пропустит.

## Последний лист

«Последний лист ВКР» с текстом о самостоятельном выполнении работы добавляется в
конец (после приложений) с новой страницы; ФИО — из `title_page`, подпись и дата —
**только от руки**. Коллективная ВКР — строка на каждого участника.

| Стиль | Назначение |
|---|---|
| `Normal` | основной текст |
| `Heading 1`, `Heading 2` | разделы и главы; параграфы |
| `VKR Title` | титульный и последний лист |
| `VKR Caption` | «Таблица N», заголовки таблиц, подписи рисунков и листингов, «Источник: …» |
| `VKR Listing` | строки кода |

## Генерация

Черновики и формат — `references/drafts-format.md`; сборка:

```text
python <SKILL_DIR>/scripts/build_vkr.py <PROJECT_DIR>
```

Прямой вызов рендерера и полный формат входного JSON — `references/docx-input-schema.md`.

## Проверка готового файла

После сборки — шаги, которые называет `build_vkr.py` (`drafts-format.md` →
«Что проверяет сборка»): `update_docx_fields.py <PROJECT_DIR>/final/vkr.docx` (без
Word — Ctrl+A, F9 и сохранение) → `clean_docx_metadata.py <PROJECT_DIR>/final/vkr.docx --in-place`
→ `vkr_audit.py <PROJECT_DIR> validate` (валидатор с профилем из
`vkr-project.json`). Глазами проверить:
- титульный лист на одной странице и заполнен;
- содержание обновлено, приложения видны как «Приложение N. Название»;
- нумерация видна со страницы 2;
- главы и приложения начинаются с новой страницы, пустых страниц нет.

Серьёзность проверок валидатора зависит от профиля:

| Нарушение | `mpgu-*` | `generic` |
|---|---|---|
| Главы пронумерованы арабскими цифрами («Глава 1.» вместо «Глава I.») | ошибка | предупреждение |
| Список литературы не в алфавитном порядке | ошибка | предупреждение |
| Нумерация страниц начинается заново в новом разделе | ошибка | предупреждение |
| Номер страницы на титульном листе | ошибка | ошибка |
| Первая страница раздела без номера | ошибка | ошибка |
| Заголовки набраны не Times New Roman | ошибка | ошибка |

Полный перечень — `submission-checklist.md` → «Формальные требования».
