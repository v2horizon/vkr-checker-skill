# 📚 Инструкция для друга — ВКР с помощью Claude Skill

Скилл - набор инструкций и инструментов для проверки, аналитики, написания черновой Выпускной работы. Не заменяет человека, а лишь помогает в написании проекта.

## Что в наборе

- `vkr-mpgu-v6.26-friends.skill` — сам скилл (≈ 470 КБ архив)
- `FRIEND-INSTRUCTIONS.md` — этот файл

## Что делает скилл

- Помогает написать черновик ВКР на 40-60 стр. за 2-4 недели (для проектной ВКР, IT-направления — 09.03.02)
- Генерирует .docx со всеми требованиями МПГУ (поля 35/10/20/20 мм, TNR 14, интервал 1.5)
- Форматирует список литературы по ГОСТ Р 7.0.100-2018
- Проверяет работу на формальные нарушения, ИИ-клише, готовность к защите
- Подготавливает к ответам на вопросы комиссии

## ⚠️ Перед началом — координация с другими пользователями скилла

**Это критично.** Если несколько твоих знакомых тоже пользуются этим скилом и сдают в один сезон — без координации Антиплагиат.Вуз увидит совпадения между вашими работами.

### Что согласовать (30 минут разговора)

1. **Темы должны быть из разных категорий продукта:**
   - бот (Telegram/чат)
   - веб-приложение
   - мобильное приложение
   - VR/AR
   - игра / интерактивный контент
   - методическое пособие / курс
   - физический/аппаратный проект

   Если у двоих всё равно «бот» — расходимся по платформам / целевым аудиториям.

2. **Стеки разные** (Python vs Node, Unity vs Unreal, React vs Vue)

3. **Базы пилота разные** (разные школы / институты / организации)

4. **Зафиксировать в общем документе** (Telegram-pin, Google Doc, Notion):

```
| Кто     | Тема | Категория | Стек | База пилота | Ветвь Главы 3 |
|---------|------|-----------|------|--------------|---------------|
| Имя 1   | ...  | бот       | aiogram | ИМО МПГУ | Б             |
| Имя 2   | ...  | VR        | Unity   | школа №X | А             |
| Имя 3   | ...  | веб       | React   | колледж Y | А             |
```

### Что НЕ передавать друг другу

- Свой `vkr-state.md`
- Свои `drafts/*.md`
- Свои якорьки (личный стиль)
- Финальный `.docx`

Делитесь только идеями и опытом, не файлами.

## Установка (5 минут)

### Вариант 1 — Claude Code (CLI/IDE интеграция)

```bash
# Распаковать в стандартную директорию скиллов
unzip vkr-mpgu-v6.26-friends.skill -d ~/.claude/skills/vkr-mpgu/
```

После этого в любом чате Claude Code скилл подключается автоматически, когда ты упоминаешь ВКР, диплом, выпускную работу.

### Вариант 2 — Claude.ai (web/Desktop) через Project

1. Создай новый Project на claude.ai → дай ему название «ВКР МПГУ»
2. Распакуй `.skill` файл (это обычный zip):
   ```bash
   # macOS / Linux
   unzip vkr-mpgu-v6.26-friends.skill -d vkr-mpgu/

   # Windows PowerShell
   Expand-Archive vkr-mpgu-v6.26-friends.skill -DestinationPath vkr-mpgu/
   ```
3. В Project Knowledge загрузи весь распакованный `vkr-mpgu/` как папку
4. В System Prompt Project'а добавь:
   ```
   У тебя есть скилл vkr-mpgu для написания ВКР по методичке МПГУ.
   Используй файлы из Project Knowledge как источник истины.
   Начни с чтения SKILL.md.
   ```

### Установка Python (нужно для скриптов скилла)

```bash
# Проверка
python3 --version    # должно быть >= 3.10

# Установка зависимостей

```

## Подготовка перед первой сессией (30-60 минут)

### 1. Сгенерируй свой `user_seed`

Это твой уникальный идентификатор. Используется в скилле для индивидуализации.

```bash
python3 -c "import secrets; print(secrets.token_hex(4))"
# пример вывода: a3f2b8c1
```

**Запомни этот seed** — он у тебя постоянный на всю работу.

### 2. Сгенерируй свой `cliche_allowlist`

Это 6 «допустимых» клише, которые в **твоей** работе НЕ будут считаться нарушением. Через свой seed — у тебя список разный с друзьями:

```bash
cd ~/.claude/skills/vkr-mpgu/   # или куда распаковал
python3 -c "
import json, random
random.seed('a3f2b8c1')           # подставь СВОЙ seed
cliches = json.load(open('data/ai_cliches.json'))['strong']
print(random.sample(cliches, 6))
"
# пример: ['стоит отметить', 'в свою очередь', 'в современном мире', ...]
```

Сохрани этот список — пойдёт в state-файл.

### 3. Собери свои тексты для personal_style_profile

Это **главная защита** уникальности работы. Принеси Claude'у:

- 2-3 README твоих публичных или приватных проектов (репозитории, документация)
- 5-10 длинных сообщений из рабочих/учебных чатов где ты что-то объясняешь технически (ТВОИ сообщения)
- Любую техническую статью / пост / инструкцию что писал
- Курсовые / рефераты прошлых лет (.docx)

**Если ничего нет** — найди хотя бы переписку, где ты подробно отвечал на вопросы по своей теме. Совсем без своих текстов скилл скатится к среднестатистическим оборотам, которые могут совпадать с другими пользователями.

Сохрани всё в один файл `my-texts.txt` или папку `my-texts/`.

### 4. Создай свой `vkr-state.md`

Шаблон лежит внутри скилла: `references/state-file-pattern.md` — скопируй и заполни.

**Обязательные поля:**

```yaml
# Мета
- Студент: [Твоё ФИО]
- Вуз: МПГУ (или твой вуз)
- Институт: [твой институт]
- Направление: [код XX.XX.XX и название]
- Профиль: [с сайта кафедры]
- Научный руководитель: [должность, степень, И.О. Фамилия]
- Заведующий кафедрой: [степень, И.О. Фамилия]
- Дата защиты: [примерная]
- Формат ВКР: проект (или обычная)

# Продукт
- Тип: [бот / веб / VR / ...]
- Стек: [языки, фреймворки, версии]
- Состояние: [в проде / прототип / в разработке]
- Educational frame: [как продукт работает в образовательном контексте — 2-3 предложения]
- product_ownership_depth: [deep / medium / low]

# Diversification (критично для friend-sharing!)
target_grade: "4+"           # или 4 / 5 — у тебя ДРУГОЕ чем у друзей
user_seed: "a3f2b8c1"        # из шага 1
cliche_allowlist:            # из шага 2
  - "стоит отметить"
  - "в свою очередь"
  - ...

structural_choices:
  ch3_branch: "А"             # А = 4 параграфа канон, Б = 7 для IT (требует согласия научрука)
  ch2_competitor_format: "swot"  # swot / tows / pestel / matrix-6col — у тебя ДРУГОЕ чем у друзей
  intro_order: "standard"     # standard / methodology-first — у тебя ДРУГОЕ чем у друзей
```

## Порядок работы (для проектной ВКР)

| День / неделя | Что делается |
|---|---|
| Сессия 1 | Intake-интервью + Глава 3 первые параграфы |
| Сессия 2-3 | Завершение Главы 3 |
| Сессия 4-5 | Глава 2 (анализ среды + конкуренты) |
| Сессия 6-7 | Глава 1 (теоретическая) |
| Сессия 8 | Заключение + Введение + Аннотация |
| Сессия 9 | Финализация sources.json (≥25 источников, проверенных через web_search) |
| Сессия 10 | Сборка .docx через `create_vkr_docx.py` |
| Сессия 11 | Прогон трёх валидаторов + правки |

При темпе 2-3 сессии в неделю → 4-5 недель на черновик.
При экспрессе (5-8 часов в день) → 7-14 дней.

## Команды скилла (после установки Python-зависимостей)

```bash
# Сборка финального .docx из drafts + state-файла
python3 ~/.claude/skills/vkr-mpgu/scripts/create_vkr_docx.py vkr-input.json -o vkr.docx

# Формальная валидация (поля, шрифт, длины глав, местоимения, ИИ-клише)
# ВАЖНО: запускай ИЗ ДИРЕКТОРИИ где лежит твой vkr-state.md —
# тогда cliche_allowlist подхватится автоматически
python3 ~/.claude/skills/vkr-mpgu/scripts/validate_vkr.py vkr.docx

# Детектор ИИ-паттернов (burstiness, перплексия, пассив)
python3 ~/.claude/skills/vkr-mpgu/scripts/ai_detection_heuristic.py vkr.docx

# Симуляция вопросов комиссии — для подготовки к защите
python3 ~/.claude/skills/vkr-mpgu/scripts/content_ownership_check.py vkr.docx --section chapter3

# Форматирование библиографии по ГОСТ
python3 ~/.claude/skills/vkr-mpgu/scripts/format_bibliography.py sources.json -o bibliography.docx

# Извлечение источников из docx + проверка существования через web_search
python3 ~/.claude/skills/vkr-mpgu/scripts/verify_sources.py --extract vkr.docx -o sources.json
```

## ⚠️ Перед сдачей — обязательные шаги

### 1. Обновить оглавление в Word (F9)

После генерации .docx — открой в **Word** (не LibreOffice — он может сломать TOC):
1. Найди раздел «Содержание» — там плейсхолдер
2. Правый клик → «Обновить поле» → «Обновить целиком»
3. Появятся заголовки + номера страниц

Без этого работа уйдёт на нормоконтроль с пустым оглавлением.

### 2. Очистить метаданные docx

```bash
python3 ~/.claude/skills/vkr-mpgu/scripts/clean_docx_metadata.py vkr-final.docx \
    -o vkr-submit.docx --seed a3f2b8c1   # подставь СВОЙ seed
```

Этот скрипт убирает идентифицирующий fingerprint (включая default `author='python-docx'`, который иначе одинаковый у всех пользователей скилла) и сдвигает created/modified в случайное окно.

### 3. Test-30 (за 2 недели до защиты)

Каждый день 20 минут:
- Открываешь случайную страницу ВКР
- 30 секунд на каждый абзац — пытаешься объяснить устно своими словами
- Если не получилось — переписываешь / изучаешь тему глубже

Это **не пропускать**. Самый недооценённый риск на защите — комиссия задаёт вопрос по абзацу, который студент не может объяснить.

### 4. Справка о внедрении (для проектной ВКР)

Шаблон: `assets/implementation-certificate.docx` внутри скилла.

1. Распечатать
2. Заполнить
3. Подписать у руководителя организации, где проводился пилот (директор школы, координатор программы, руководитель отдела)
4. Живая ручка, желательно печать

Без этой справки проектную ВКР обычно не допускают к защите.

## Если что-то идёт не так

| Проблема | Решение |
|---|---|
| Claude уходит в общие формулировки | Напомни: «применяй humanizer-techniques.md, target_grade=твой_grade, ownership=deep/medium» |
| Список литературы выглядит подозрительно | `verify_sources.py --extract`, проверь сомнительные через Google Scholar |
| Контекст забивается на 7-8 сессии | Открой новую сессию, приложи свежий state-файл и последнюю готовую главу |
| Научрук не согласовал тему | Внутри скилла: `references/failure-recovery.md` |
| Дедлайн ближе чем казалось | Внутри скилла: `references/writing-workflow-express.md` |

## Главное правило

**Скилл — инструмент. Защита — твоя.**

Скилл напишет 70-80% текста, обеспечит формальное соответствие методичке, поможет с источниками. Но:
- Ответственность за содержание — на тебе
- Знание материала на защите — твоё
- Реальный продукт и пилот — не генерируются
- Согласование с научруком и кафедрой — твоё

Цель скилла — **сэкономить время на оформлении и стилевой подгонке**, чтобы ты сосредоточился на содержании работы и подготовке к защите.

Удачи на защите.
