# vkr-mpgu v6.26-friends — Quickstart для друзей

Это версия скилла для **передачи друзьям**, которые тоже пишут ВКР в МПГУ. Содержит дополнительную защиту от кросс-матчинга — статистических совпадений между работами разных пользователей одного скилла.

## Чем отличается от personal-версии

| | Personal (v6.25) | Friends (v6.26-friends) |
|---|---|---|
| Базовый функционал | Полный | Полный |
| Скрипт `clean_docx_metadata.py` | Нет | **Есть** — обнуляет fingerprint docx |
| Файл `references/friend-sharing.md` | Нет | **Есть** — протокол координации |
| `validate_vkr.py` читает `cliche_allowlist` из state-файла | Нет | **Да** — индивидуальные клише не помечаются |
| 4 альтернативных формата таблиц анализа (SWOT/TOWS/PESTEL/matrix-6col) | Нет | **Есть** в `project-templates.md` |
| 2 варианта порядка введения (`standard` / `methodology-first`) | Нет | **Есть** в `structure-project.md` |
| Поля state-файла `user_seed`, `target_grade`, `cliche_allowlist`, `structural_choices` | Нет | **Документированы** в `state-file-pattern.md` |
| Защита от автоматического `author='python-docx'` | Нет | **Есть** через `clean_docx_metadata.py` |

## Перед раздачей друзьям — обязательно прочитать вместе

Сядьте все вместе **до того, как кто-то начал писать**. 30 минут.

### 1. Координация тем (главный шаг)

Каждый берёт разную категорию продукта: бот / веб-приложение / мобильное / VR / обучающая игра / методическое пособие / аппаратный проект.

Если двое всё равно делают боты — расходитесь по платформам / целевым аудиториям / функциональному фокусу.

### 2. Зафиксировать договорённости в общем документе

```
| Студент | Тема | Категория | Стек | База пилота | Сдача | Ветвь Главы 3 |
|---------|------|-----------|------|--------------|-------|---------------|
| А       | ...  | бот       | aiogram | ИМО МПГУ | июнь  | Б             |
| Б       | ...  | VR        | Unity  | школа №X | июнь  | А             |
| В       | ...  | веб-app   | React  | колледж Y | июнь  | А             |
```

### 3. Структурные различия в Главе 2

- А: SWOT 2×2 + таблица конкурентов 6 столбцов
- Б: PESTEL 2×3 + матрица 4×4
- В: TOWS + сравнение по 3 критериям

## Как установить и стартовать (для каждого друга)

### Шаг 1. Распаковать скилл
```bash
unzip vkr-mpgu-v6.26-friends.skill -d ~/.claude/skills/vkr-mpgu/
```

### Шаг 2. Сгенерировать свой user_seed
```python
import secrets
print(secrets.token_hex(4))   # например: a3f2b8c1
```
Сохранить — это твой постоянный seed на всю работу.

### Шаг 3. Сгенерировать свой cliche_allowlist через seed
```python
import json, random
random.seed("ваш_user_seed")
cliches = json.load(open("data/ai_cliches.json"))["strong"]
my_allowlist = random.sample(cliches, 6)
print(my_allowlist)
```
Эти 6 клише **не вырезаются** в твоей работе — снижает странность отсутствия популярных оборотов.

### Шаг 4. Создать свой state-файл
Скопировать шаблон из `references/state-file-pattern.md`, добавить:
```yaml
user_seed: "a3f2b8c1"
target_grade: "4+"          # или 4, или 5 — каждый разный!
cliche_allowlist: [...]     # 6 случайных через seed
```

### Шаг 5. Запустить Claude
```
Привет. Я пишу ВКР в МПГУ. Прикладываю state-файл.
В нашем потоке скилл vkr-mpgu используют ещё [число] человек —
обязательно прочитай references/friend-sharing.md и применяй его правила.

[прикрепляешь vkr-state.md и свои тексты для Этапа 7]
```

### Шаг 6. Перед сдачей — обязательно очистить метаданные
```bash
python scripts/clean_docx_metadata.py vkr-final.docx -o vkr-submit.docx --seed a3f2b8c1
```
**Без этого** у всех друзей docx будет иметь одинаковый `author='python-docx'` fingerprint.

## Что НЕ делать

❌ Не передавай друзьям свой state-файл, sources.json, drafts, якорьки, финальный docx
❌ Не используйте одни и те же темы / стеки / базы пилота
❌ Не пропускайте Этап 7 интервью — без своих текстов работы будут похожи
❌ Не забывайте `clean_docx_metadata.py` перед сдачей

## Финальное правило

**Главная защита — НЕ скилл, а индивидуальная конкретика твоего продукта.**

Скилл даёт +20-30% защиты, остальное — твои реальные данные пилота, версии стека, имена компонентов.

Подробности — в `references/friend-sharing.md` внутри скилла.
